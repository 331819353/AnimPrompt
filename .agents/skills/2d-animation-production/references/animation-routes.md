# 动画制作路线

进入动画制作时让用户选择下列一条路线，沿用已有明确选择；只写剧本不要求选择。最迟在清单确认、生成人物或场景参考前确定，可与清单一起询问，无需增加重复审阅。选择前可继续剧本、清单和只读能力核对，不代选、不同时投产两路。

用户触发词为“连续动画”和“翻页动画”：明确要求制作或选用其中一种时直接记录选择；只是比较、询问或同时讨论两种方式不算选择。用户界面与沟通统一使用这两个名称，内部记录值保持兼容，路线名不表示已经保证运动流畅。

| 用户选项 | 记录值 | 制作方式与取舍 |
| --- | --- | --- |
| 连续动画 | `keyframe-video` | 默认开始、过渡、结束三张关键图，相邻两图生成视频；独立图片较少，须验证片内运动、片间连接及生成费用 |
| 翻页动画 | `frame-sequence` | 每个可见变化至少六张有效不同的完整图片，逐张微调、本地换帧；可逐图修复，图片制作量较大，连续性依赖姿势与定时 |

展示区别及当前能力、报价的已知与未知部分，不预先承诺哪路更便宜、更快或必然一致。没有明确选择时保持待选择；普通“全权创作”或“跳过审稿”不等于授权代选，用户明确让 Agent 选择路线时才按其范围记录决定。两路共用剧本、画风、参考、画布、Fish 配音、连续性自查与分段交付，路线不绑定画风。

## 连续动画

1. 按“事件→场景→镜头→关键状态”规划，一个镜头可同时承载动作、表情和场景交互，不把每个变化分别扩成两段视频。先核对实际对白、停顿、动作和反应的时间；需要准确发声表演的镜头取得选用真实配音后再生成视频。
2. 清单确认后建立共用标准参考，按镜头规划开始 `K01`、过渡 `K02`、结束 `K03` 三种状态。按下方逐片确认规则，只生成当前片段所需关键图；`K01→K02` 确认后才生成后续 `K03` 及 `K02→K03`。同对图片宽高比一致，满足接口尺寸要求；从同一镜头基准编辑，核对身份、比例、服装、空间、光照和历史版本。
3. 过渡图表达关键接触或转折，不只是时间中点。递物、落座、开门等按需要增加握住、松手、支撑、通过或回应状态；静止镜头不强凑三图。跨地点、机位或时段按剪辑建立新镜头，不生成两场之间的变形过渡。
4. 当前关键图入统一画布，自查并补齐本片段剧情/线索覆盖，经该范围画布确认后生成当前图片对的视频。读取实时模型、素材槽位、时长、分辨率与报价，确认确实支持双图首尾。标准参考用于关键图，不在仅允许双图的模式中额外塞第三张，也不把多图参考误记为明确首尾控制；不得并发提交前后片段。
5. 5 秒可作为每次生成的起始方案，按镜头需要和实时模型范围调整；不默认每组必须采用完整的两段 5 秒。生成时长、实际文件时长、剪辑入出点及最终采用时长分别记录。裁剪不删关键接触和结果，不用整体变速硬塞对白，也不用静帧或重复片段凑各段时长。
6. 为每一对明确运动主体、路径、先后、速度、接触/支撑、镜头运动及允许变化，防止自行加动作、切镜头或改变背景。相邻视频共用关键图仍须核对实际输出首尾；连接还要检查方向、速度、握持和情绪，不默认姿势相同就流畅，也不强制每个连接都停顿。可用上一段实际合格尾帧接续，先确认它仍符合目标状态和标准参考；改变了已确认动作结果则更新对应确认，不沿用漂移帧扩散错误。
7. 视频生成只负责画面及需要的环境声/动作音效，提示不生成对白、旁白或其他人物人声；全部配音由 Fish 提供。首尾帧不等于口型同步，正面对白核对真实配音与嘴形，仅在接口支持时提供音频参考，不编造参数。无法同步时修复或重生成，改变镜头或路线按用户决定；声轨取舍按下方分工处理。
8. 检查全部采用关键图、实际生成片段和全部连接。对片内运动逐帧检查，正常速度检查节奏，异常处慢放；覆盖脸/服装/背景与纸纹漂移、多手多脚、头身扭转、滑步、穿透、道具朝向、关键接触、结果、口型和片间跳变。不能只查看三张关键图或抽看首尾就判视频通过；检查能力不足时标明未核验范围。

视频优先经即梦生成，报价与积分授权沿用 [核验原则](canvas-and-image-routing.md#即梦优先与额度检查)，针对当前片段的视频能力、额度和费用另行确认。Image Gen 只负责图片，Fish 负责配音，两者不生视频。当前片段不合格时修复，视频不可用时提供改走翻页动画的具体方案，由用户决定，不自动换路。

## 翻页动画

标准参考及首尾关键图入画布、自查并确认后，规划中间姿势，按 [上一帧微调](visuals-and-performance.md#标准参考图与上一帧微调) 顺序生成完整图片。每个变化遵守 [至少六张有效图片](visuals-and-performance.md#变化单元与至少六张有效图片)，复杂动作继续补帧，用户指定 12 张等数量时沿用该范围。

每张以前一合格帧为编辑目标，标准参考核对身份，尾帧约束终点；发声序列依据真实配音安排嘴形与身体联动。逐张检查及整组对齐后，由本地工程按动作定时整图替换，不拆身体部件，不用交叉淡化掩盖缺步。完整方法见 [多帧切换](visuals-and-performance.md#用多帧切换补足连续动作)。

六张下限仅用于翻页动画的独立动作图片，不叠加到连续动画；连续动画的视频输出帧、抽帧或复制图片也不用于冒充翻页动画的六张独立图片。

## 逐片生成与用户确认

“片段”是短视频/完整动作单元，不是约 3–5 分钟的上、中、下叙事段。连续动画每个相邻关键图生成的视频是一个片段，例如 `K01→K02` 与 `K02→K03` 分别确认；翻页动画以一个镜头内可独立预览的短动作单元合成一个片段，内部每个变化仍至少六张。不把整集或多个未审动作打包成一个片段绕过确认。

1. 在现有镜头/时间轴计划中分配稳定 `clip_id`，如 `P01_C001`，记录顺序、剧情范围、时长依据、前后状态和当前待制作位置。全局文字计划、配音稿及共用标准参考可先准备；后续片段专属关键图、补帧、视频、配音和音效不提前生成，已确认终态可复用；跨片同一句台词可按 [共享 Fish 音源](voice-and-audio.md) 生成完整句并记录引用范围，不扩展到后续专属台词。
2. 仅投产当前片段；本片段中没有依赖关系的工作可并行，发声动态素材仍先取得本片段真实 Fish 配音。生成、修复、自查后输出可播放预览，包含采用配音、所需音效/环境声及对应字幕，并检查与已确认前片的连接；静音剧情可无配音，但不能用待补声音的占位预览代替完成。
3. 向用户提供当前片段实际文件、内容范围及需要判断的问题。用户明确认可该版本后，保存 `user_review.clips[clip_id]` 的 `confirmed`、预览版本/路径、决定依据及前片依赖，才开放下一片段。待回复、修改中或 `needs_reconfirm` 时仅处理当前问题和独立准备，不提前提交下一片段任务；沉默、自查通过、清单/关键图确认、整集授权及首片确认不代替后续逐片确认。
4. 首片兼作表现样片，不强凑十至十五秒；不得先生成多个未确认片段再拼成样片送审。后续每片沿用同一循环，已确认片段可拼接复查持续性；修订已确认素材时保留旧版本，标记受影响确认失效，复查后重新确认，再从最早未满足条件的位置接续。

除非用户之后明确调整具体片段范围的审阅规则，两路均执行逐片确认；旧的笼统“全权制作”不视为取消本次要求。写作、共用参考的既有确认节点仍保留，逐片确认不免除完整故事、分段导出和全片自查。

## 画面、音效与 Fish 配音

- 连续动画的视频工具负责画面与非人声环境/动作音效；模型不支持所需音效时记录实际能力，使用可用音效工具或素材补齐，不声称视频已生成该音效。翻页动画以本地换帧制作画面，音效独立生成或取自素材，不为音效强制改走连续动画。
- 对白、旁白、内心独白及人物笑声/叹气等配音均由 Fish Audio MCP 按限定音色生成；视频模型的人声不进入正式选用。配乐独立组织，视频生成不擅自添加配乐或演唱。
- 按实际声轨分离画面、音效/环境声、Fish 配音和音乐。保留合格的生成音效，去除误生人声；若混在同轨且无法干净去除，重生成或另配所需音效，不把整轨静音后仍称音效完整。统一登记来源、采用版本和定时，检查同步、抢声、重复叠加和听感，详见 [音效与混音](voice-and-audio.md#环境声动作音效与音乐)。

## 选择、记录与切换

- 在 `project_state.json` 保存 `animation_route`、适用范围和用户选择依据，在 `user_review.animation_route` 记录决定；可与清单确认同次完成。新增路线或变更仍需用户明确决定；已有明确选择不重复询问。
- 共用 `asset_manifest.json` 与时间轴。连续动画记录镜头及关键图顺序、每对首尾版本、实际模型/参数、任务和节点、原视频/工程副本、实际时长/尺寸/帧率、采用入出点、实际首尾检查、连接及修复状态；翻页动画保留变化单元、有效图片数、上一合格帧、帧序、锚点和持续时间。报价、授权、采用版本和检查证据指向实际结果，不维护重复清单或保存凭据。
- 两路均按 [逐片确认](#逐片生成与用户确认) 顺序推进，连续动画检查片内及与已确认前片的连接，翻页动画检查相邻换帧；实际演出场景交互及结果，跨镜头、跨线和跨段保持 [事件连续性](story-continuity.md)。恢复时先核对逐片确认及文件版本，不因 `sample: confirmed` 批量开放后续生成。
- 用户改变路线时只更新指定范围，复用仍合格的剧本、参考、关键图和声音，重做受影响动作/视频、时间轴及样片检查。明确允许局部采用另一条路线时逐镜头记录，不能静默把同一动作的两套标准混在一起。
- 续作先核对原选择与版本。旧工程可依据实际素材识别原方法并记录推断依据，但推断不等于用户选择；找不到明确决定时先确认再投产。待查询旧任务先恢复结果，不重复提交。旧工程已有后片文件保留并按顺序审阅，不因文件存在或旧样片确认就放行后续生成。
