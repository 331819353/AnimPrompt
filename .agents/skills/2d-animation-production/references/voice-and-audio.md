# 配音与音频

整理录音稿或生成、核验、修复声音时读取相关内容；混音时读取环境声、音效和音乐要求。对白与旁白由 Agent 通过 Fish Audio MCP 生成，按用户当前范围推进，阶段交接及恢复见 [阶段衔接与续作](handoff-and-resume.md)。

Fish Audio MCP 在本流程仅用于音频：选声、试听、语音合成、转写及音频核验。按用户实测，不将其用于图片或视频生成、编辑、图生视频、自动口型或数字人；图片与画布工作按 [即梦优先、Image Gen 备用](canvas-and-image-routing.md) 执行。音频额度与配音可用性不用于推断图片/视频可用性，旧视觉测试计划不自动恢复。

Agent 组织正文、选声、行内标签和调用结果；声音文件的解码、时长、波形、混音与工程定时使用可用本地工具。语气和读音的实际听音检查、转写及技术检查分别记录，适用能力边界见 [制作执行与能力边界](production-execution.md#检查依据与适用边界)。

分段剧本确认后整理录音稿；角色清单确认且录音稿输入齐备后，再选声试听与生成配音。音频可与已放行的首尾帧/画布工作并行，但不能因此提前投产尚未确认的中间帧；最终嘴形与表演定时依实际声音核定。

内容：录音稿；工具就绪与音色；标签的选择、位置、示例及修复；按叙事段生成；音频版本与成片时间映射；环境声、动作音效与音乐。

## 录音稿与 Fish Audio MCP 配音

你负责整理录音稿，并通过 Fish Audio MCP 完成选声、标签设计、试听、生成和问题段修复。各环节统一使用以下内容定义：

| 内容 | 定义与用途 |
| --- | --- |
| 朗读正文 | 应读出的对白、旁白与必要拟声词，是台词校验和字幕文字的依据 |
| 表演说明 | 角色、语气、动作、读音提示与标签意图，单独保存在制作表中 |
| 生成文本 | 以朗读正文为基础，按需加入声音标签和工具支持的读音处理，作为实际配音输入 |
| 定稿配音 | 确定选用、完成必要格式整理并保存逐项核验状态的配音文件，保留与原始结果的对应关系；未完成听音的项目明确标注，不能登记为试听通过 |
| 成片时间轴 | 各叙事段从零开始的视频时间轴及其与整体剧情顺序的对应；本段定稿配音、动作、状态变化、信息展示、留白、镜头与声层共用定时依据，跨段状态延续 |

### 整理完整录音稿与生成清单

1. 从已确认的采用剧本提取全部需要发声的人物对白、必要旁白及明确需要朗读的片头、片尾内容，保持剧情顺序与核心含义。保留 [生活化对白](scriptwriting.md#对白保留自然说话的过程) 中的口语衔接、铺垫、重复和补充，不为缩短录音或适配镜头而压成摘要；需要实质改写时回到剧本修订与确认。不擅自新增旁白，也不把动作说明、角色名或叙事段编号当作台词朗读。
2. 沿用采用剧本及制作方案已确认的上/下或上/中/下叙事段与边界，不重新划成章、节。每段内部按自然语义组织配音段落，与原场景建立对应关系；接口长度限制只产生技术分片，不改变叙事边界，也不在一句话或完整动作中途截断故事。用户指定的已有剧本保留核心内容，按制作时确认的分段整理，避免漏句、重复或顺序错误。
3. 整理为一份完整的“录音稿.md”，包含采用剧本的叙事段目录、角色表和按播放顺序排列的台词段；话题生成的作品使用上/下或上/中/下目录。每个自然语义段设置固定编号，例如 P01_D001，分别保存朗读正文、表演说明和初始生成文本；叙事段标题默认不朗读，用户明确要求时才读出。
4. 朗读正文保留标准台词，角色名、编号和导演说明单独记录。生成文本可按表演需要加入标签，普通自然表达可以不加。处理多音字、人名、地名或缩写时，保留标准写法并记录实际读音处理；生成文本与正文的差异须可追溯且不改变含义。
5. 附音频生成清单，包含叙事段、段落编号、角色、朗读正文、生成文本、表演意图、正文与生成文本版本、计划音色及目标文件名。段落编号保持稳定；初稿中的音色和标签可随试听更新，修改后按下方版本规范保存。
6. 对照采用剧本逐段自查全部叙事段的角色、顺序、正文覆盖、口语表达、标签/说明区分、版本与生成清单，修复漏句、重复、误归角色等问题并复查后再交付完整录音稿和清单。本次目标为动画或成片时，先推进样片所需的图片与配音，按 [用户沟通与确认](handoff-and-resume.md#用户沟通与确认) 取得样片反馈后再批量生成其余叙事段。正文、生成文本与最终选用音频持续保持对应；录音稿与已生成声音的自查证据按 [阶段自查与放行](handoff-and-resume.md#阶段自查与放行) 保存。

### 标签使用：按剧情设计声音表演

按当前 Fish Audio MCP 文本接口的行内控制方式，在生成文本中用半角方括号 `[标签]` 写表演指令。标签不是台词或字幕，实际响应通过生成结果核验；不将某个模型名设成无法传入的参数。[官方情绪控制说明](https://docs.fish.audio/developer-guide/core-features/emotions)、[MCP 标签说明](https://docs.fish.audio/overview/mcp)

#### 常用标签与选择依据

以下标签是选用起点，具体效果须结合音色试听；不用逐句加标签，也不用把所有类别同时组合。[官方标签参考](https://docs.fish.audio/developer-guide/core-features/emotions)

| 表演目的 | 标签示例 | 使用判断 |
| --- | --- | --- |
| 主要情绪 | `[calm]`、`[excited]`、`[sad]`、`[angry]` | 根据人物当下处境选择；愤怒的强度由剧情决定 |
| 疑虑与发现 | `[nervous]`、`[uncertain]`、`[confused]`、`[surprised]` | 区分紧张、不确定、不理解和突然发现 |
| 对话态度 | `[sarcastic]`、`[empathetic]`、`[determined]` | 根据人物意图表现反讽、体谅或决心 |
| 发声方式 | `[whispering]`、`[soft tone]`、`[shouting]` | 根据距离、保密需求与冲突强度选择 |
| 局部重音 | `[emphasis]` | 放在需要强调的词或短语前 |
| 人物反应 | `[chuckling]`、`[sighing]`、`[gasping]`、`[panting]` | 用于剧情需要的轻笑、叹气、倒吸气或喘息 |
| 停顿 | `[pause]`、`[long pause]` | 按当前接口支持的行内描述提示语气停顿或较长留白，实际时长另行核验 |

当前接口允许简短的开放域描述，中文和英文均可用于细化表演，不限于表中的标签。例如自拟 `[压住火气，保持礼貌]`、`[强装轻松，尾音略有犹豫]`；先用短段生成和核验，再决定是否保留。自由描述属于可尝试的表演指令，不代表固定参数或必然达到预期。[官方自然语言标签指南](https://fish.audio/blog/fish-audio-s2-fine-grained-ai-voice-control-at-the-word-level/)

#### 位置、组合与节奏

1. 整句情绪一般放在句首；局部变化放在要改变的词句前。反应标签放在反应发生处，语气切换时在相应位置写新标签。标签影响后续表达，不能把句首标签当成只控制句末的指令。[官方位置与组合指南](https://fish.audio/blog/how-to-use-inline-tags-in-fish-audio-s2/)
2. 普通对话可以保持自然表达；需要控制时，先选一项主要情绪，再按需要叠加发声方式或人物反应。对同一处表演避免相互冲突的指令；“表面客气、心里不满”可用简短描述表达，不机械叠加多个相反情绪。
3. 强度与角色身份、关系和场景匹配。低音区标签 `[low voice]` 与耳语不同；情绪标签也不负责切换角色音色。重要转折要有前后变化，旁白、日常交流和冲突场景各用合适的力度。[官方声音风格指南](https://fish.audio/blog/how-to-use-inline-tags-in-fish-audio-s2/)
4. 停顿标签是表演提示，不能据此承诺固定秒数。先核对实际声音和停顿位置，需要精确留白时在工程副本中安排时间，保留语义停顿与自然句尾；嘴形和动作依据实际声音定时。
5. 描述语气的标签后应有可朗读正文，不把空标签当成稳定的独立声音素材。人物反应是否实际发声须试听确认；拟声词只在剧情需要时写入正文。配乐和场景环境声仍按 [环境声、动作音效与音乐](voice-and-audio.md#环境声动作音效与音乐) 单独组织。[官方试听与标签建议](https://fish.audio/blog/fish-audio-s2-fine-grained-ai-voice-control-at-the-word-level/)

#### 中文台词示例

以下为写法示例，不是已生成或验证的音频。角色名、编号和解释保留在制作表中；提交给配音工具的文本只包含标签与对应正文。

| 情境 | 生成文本 | 表演意图 |
| --- | --- | --- |
| 紧张地提醒同伴 | `[nervous][whispering] 别出声，他们还在门外。` | 情绪与保密场景共同决定表达 |
| 局部强调 | `[calm] 这件事必须[emphasis]今天[calm]完成。` | 突出“今天”，随后恢复平稳语气 |
| 安慰受挫的人 | `[empathetic][soft tone] 先坐下，咱们慢慢想办法。` | 关切、温和，保持角色原有音色 |
| 喜悦转为犹豫 | `[excited] 终于轮到我了！[long pause][uncertain] 可家里怎么办？` | 在转折处改变情绪并留下反应空间 |
| 认错前的叹气 | `[sighing][sad] 这次，是我没想周全。` | 将身体反应与低落情绪联系起来 |
| 克制地表达不满 | `[压住火气，保持礼貌] 这件事，您考虑得可真周到。` | 用自由描述尝试含蓄表演，试听确认 |

#### Agent 选用与修复步骤

1. 先判断每段的说话对象、目的、情绪、表达强度和转折点，再确定标签；记录“希望听出什么”，而不是只登记标签名称。
2. 保持正文和角色音色一致，优先试一个清楚的标签或少量合理组合。关键段可比较自然表达、常用标签和自由描述，选择最符合剧情、最清楚自然的版本；结果稳定的写法可在同类情境复用。
3. 检查标签是否传入正确的文本字段、括号是否完整，以及实际语音是否达到意图。标签被读出或没有效果时，核对当前接口支持、输入处理和位置，简化或改写提示，重生成问题段并按可用能力复查；不能把“提交了标签”等同于“表演已实现”。
4. 标签是否达成表演意图以听音结果为准。调整标签产生新的生成文本版本，选用结果、版本替换和定时更新统一按下方规范管理。
5. 没有可用听音或音频理解能力时，完成可执行的转写、时长、句尾和波形检查，记录标签效果待听音核验；不以已提交标签或转写一致替代语气检查。可继续图片和工程工作，阶段完成状态依据实际核验范围保存。

### 按叙事段生成与文件整理

1. 按叙事段和自然语义段生成对白与旁白，每次调用关联角色、段落编号、正文与生成文本版本、音色和配置。只将生成文本传入工具的朗读文本字段；有标签时保留其内容和位置。按工具限制拆段，每个新段保留必要提示，拆分后的片段仍归属原段落编号，顺序和覆盖范围明确。
2. 对情绪变化较大、读音有风险或句尾易截断的段落分别生成和检查。优先取得不含音乐或音效的干声，保留剧情需要的停顿与反应空间，不在配音文本中夹入配乐或音效要求。
3. 直接配音接口返回声音 URL 或实际文件时按返回方式获取，保存到本地工程并核对格式和内容。只有工具确实返回异步任务标识时才查询进度；不为同步调用编造任务 ID。结果不确定时先核对已有响应和文件，再按当前接口的重试规则处理，避免重复生成。
4. 按叙事段建立目录，例如 audio/P01_上/；段落文件包含稳定编号和音频版本，例如 P01_D001_a02_角色甲.wav，扩展名与实际编码一致。分片文件另加顺序号；保留原始结果，格式与音量整理使用工程副本，转码准确标注来源，不将有损原件转码后称为原生无损音频。
5. 复用合格段落，在 Fish Audio MCP 中修复或重生成缺失、不合格的段落，并记录原因和结果。叙事段文件按剧情顺序组装，保留段落起止与原文件的对应关系。
6. 保存 fish_audio_mcp_settings.json 与 fish_audio_mcp_jobs.json，记录实际工具、正文与生成文本版本、提交文本、音色、可核实的模型与参数、各次结果、文件及公开任务标识（如有）。未返回的信息标注未提供，记录不包含认证凭据或临时签名地址。

### 音频定稿、版本与成片时间轴

1. 读取音频格式、时长、采样率与声道，核对正文、角色、顺序和版本。可用 `speech_to_text` 时以生成结果的真实音频 URL 辅助转写，不假定返回逐字时间戳或口型信息，转写调用的实际额度与配置单独记录。环境支持听音时逐段核对漏句、重复、读音、句尾、停顿、语气、噪声、音量及跨叙事段音色一致性，确认标签按意图表演，未被读出或引入多余声音。自动识别仅辅助定位，读音处理造成的文字差异须对照标准正文核实；没有听音条件的项目保持待核验，时间映射只使用实际文件和可确认的信息。
2. 按叙事段和段落登记问题，保持角色音色修复或重生成，按同一检查依据复查。保留台词含义与完整内容，不能通过删句、拉伸声音或覆盖音轨掩盖问题。笑声、叹气等非语言反应与说出的拟声词分别记录。
3. 正文、生成文本和音频分别保留版本。正文变化后检查生成文本；标签、读音处理或生成设置变化后记录新的输入与结果。重生成和后期整理保存新版本，保留原始文件及已选用结果。
4. audio_manifest.json 是音频选用与对应关系的统一清单。每个段落明确唯一选用结果及其分片顺序，记录正文、生成文本、音频版本，角色与音色，原始和工程文件路径，实际时长、采样率、声道、来源、技术/转写/听音核验状态及关联调用记录。其他制作表引用此清单，候选文件与正式选用文件分别标明。
5. 以实际使用的工程音频为上/下或上/中/下各段建立从零开始的成片时间轴。拼接、格式整理、添加留白或其他影响时序的处理后，重新读取时长并记录原始文件内起止、所属段标识、本段成片起止与整体剧情顺序的对应；标注发声、停顿及人物反应的实际位置。原始配音或整体工程中的时间不能直接替代本段视频的最终位置，每段 SRT 使用对应本段时刻。
6. 动作、状态变化、信息展示、镜头、嘴形、字幕与混音共用成片时间轴。视觉变化按输出帧率记录帧号，音频与字幕保留相应精度，音效对应实际发生的变化。无声表演、留白和片头片尾可占用额外时段，保留自然句尾，配音不为适配画面而拉伸。
7. 配音、表演设计、状态、信息内容或工程时序变更后，更新对应段记录和成片时间轴，复查本段后续偏移、动作、信息显示、字幕与声层，并核对后段的剧情/状态承接。导出前核对音频选用清单、场景与表演状态记录及各段时间轴的版本一致。可先制作已核验叙事段，正式配音、混音与字幕分别关联本段视频，最终交付覆盖全部要求的段。

## 环境声、动作音效与音乐

1. 使用 [配音与音频](voice-and-audio.md) 核验通过的对白与旁白，环境声、动作音效和音乐另行组织，按可得音轨分轨编排。
2. 动作音效对应实际接触、变化和叙事强调点，按成片时间轴安排，不随姿势换帧自动触发。重复展示或回忆中的声音按叙事意图组织，避免无意重复叠加。
3. 环境声在同一地点内连续保持，跨镜头自然衔接；不能随着动作循环重启。
4. 音乐服务于主题及情绪，不随着每次换帧或对白切换。以定稿对白、旁白为主体安排音效和配乐，完成音量平衡；对白期间合理降低音乐与环境声，保证理解。
5. 场景转换可以使用提前进入的下一场声音或延续的上一场声音；避免每次剪辑都添加相同的强冲击声。
6. 配乐、动作音效和环境声选用适用的现有素材，通过音频编辑工具或本地脚本剪辑、排列与混音。对白与旁白保留干声；检查素材已有声层，避免重复叠加。缺少所需素材时记录缺口并说明对成片的影响。
7. 检查音画同步、对白清楚、循环接缝自然、音层不过度叠加，无爆音和突兀切音，统一工程采样率并保留合理余量。
