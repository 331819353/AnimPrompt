# 制作执行与能力边界

在检查工具、编写或接续工程、图片技术整理、动画合成、编码和组织检查时读取。只写剧本时执行文字、资料核验和保存工作，不要求预先配置媒体运行环境。保留 [主入口](../SKILL.md) 规定的工具分工与本次范围。

通过当前 Agent 的工具发现、连接器、文件或命令执行接口完成工作，接口名称与参数以实际暴露的能力为准。Image Gen 和 Fish Audio MCP 是媒体制作工具要求；执行这些规范的 Agent、客户端及工程运行方式不作平台限定。

## 能力与执行方式

| 环节 | Agent 的执行方式 | 完成依据 |
| --- | --- | --- |
| 选题与事实核验 | 理解用户主题，使用可用搜索及读取工具核验关键事实，保存来源和事实截止日期 | 实际读取的资料、准确的适用范围及完整剧本 |
| 剧本、录音稿与制作规划 | 生成和修订文本，提取台词，编排角色/场景/叙事段/镜头标识及依赖 | 已保存的采用版本、无漏句重复的交接记录 |
| 图片创作 | 调用 Image Gen 生成或编辑完整背景、角色动作、道具、效果和封面 | 实际返回的图片、查看结果和采用版本 |
| 图片技术整理 | 使用可用图片库或像素工具读取尺寸/透明通道，按统一规则补画布、定位、格式整理及制作检查视图 | 同组尺寸与锚点数据、透明边缘及换帧检查 |
| 配音 | 通过 Fish Audio MCP 查询音色并提交生成文本，保存实际返回的声音 | 音色标识、正文/生成文本/音频对应及实际核验记录 |
| 动画与时间轴 | 编写、运行和修复本地合成工程，以完整动作图片换帧、位移、遮挡和状态变化组织镜头 | 实际渲染的样片、叙事段、时间轴与可复用工程 |
| 排版与信息显示 | 使用字体和图片/排版工具制作字幕、标题、气泡、计数器及信息图层 | 核对文本、正确的数据和定时、清楚的实际预览 |
| 混音与编码 | 调用可用音频和编码工具，优先使用本地 FFmpeg/FFprobe 或已可调用的等效工具 | 音轨/配置、完整 MP4/SRT、实际规格与解码检查 |
| 验证与续作 | 读取文件和清单，查看画面，在环境支持时播放或理解音频/视频，记录证据并处理变更 | 当前版本、检查方式/覆盖范围、未核验项及下一步 |

Image Gen 可以生成和编辑图片，但角色一致性、精确构图和文字布局仍须核验；不能把提示中的尺寸、锚点、调色板或保持条件当作已经满足。[OpenAI 图像生成能力与限制](https://developers.openai.com/api/docs/guides/image-generation)

不具备直接生成连续动画或动作视频的接口时，只要图片创作与本地合成能力可用，就按 [多帧切换](visuals-and-performance.md#用多帧切换补足连续动作) 增加完整关键姿势和过渡图片，顺序切换模拟连续动作。不要把缺少连续动画生成接口当作整片制作受阻的理由，或将原定互动缩减为固定背景对白；实际图片生成或合成能力缺失时，仍按相应阶段记录真实缺口。

## 按阶段检查运行依赖

1. 执行媒体工作前确认 Image Gen、Fish Audio MCP 的相关工具是否实际加载，阅读当前输入输出。Fish Audio 仅用于声音工作，不调用它的图片、视频或自动口型生成功能替代现有分工。
2. 使用可用的工作区依赖发现工具或 shell 检查 Python/Node、图片库、字体、媒体编码/探测工具及保存目录。优先复用当前环境可用运行时；不把某台机器的绝对工具路径写成 Skill 的固定要求。
3. 图片技术处理可使用 Python/Pillow、NumPy 或合适的等效库。像素结构、美术修复和新动作内容继续通过 Image Gen 创作；程序负责已规定的工程处理、排版和合成，不用几何占位图替代正式人物或场景。
4. 检查编码器及 H.264/AAC 支持、音频解码与中文字体的实际可用性。缺少依赖时按当前环境权限配置可用工具，或记录准确恢复条件；继续文字、图片、配音及可执行的独立工作。
5. 用本次代表性素材跑通约十至十五秒的声音定时、动作换帧、混音/字幕及 1080p 编码链路，将实际样片按 [用户沟通与确认](handoff-and-resume.md#用户沟通与确认) 提交用户判断表现效果，确认后再批量展开叙事段。依赖检查、编码测试及常规技术修复自主完成，技术通过与用户确认分别记录。

## 图片生成与技术整理

先生成并检查标准人物参考图与当前镜头初始帧，按 [变化单元与图片下限](visuals-and-performance.md#变化单元与至少六张有效图片) 为每个可见变化制作至少六张有效不同的完整图片，样片与正式动画均适用；逐个记录实际采用关系与数量，不以复制文件、重复静帧或仅增加输出帧数凑数。连续动作按 [上一帧微调](visuals-and-performance.md#标准参考图与上一帧微调) 顺序编辑，每次以上一张合格帧为目标，仅推进指定动作，并对照标准图/初始帧核对固定属性；当前帧通过检查后才继续，失真或漂移先修复。没有连续动画生成能力时按需要补足完整过渡图片，先检查一段实际序列，再扩展同类动作。每项结果仍是完整角色及相关道具、完整镜头或对应完整对象/效果帧。

将 Image Gen 选用结果复制到作品目录，保留原始结果与工程副本。记录实际宽高、透明通道、姿势组、基准版本、比例、锚点及来源。生成图片尺寸与最终逻辑画布不同并不等于可直接入工程；按整组统一规则整理并查看结果，不能逐帧紧裁、独立缩放或居中。

像素形式的采样检查与审美检查分别进行：技术处理可统一画布、网格和定位，但降低分辨率或最近邻缩放本身不能证明图片具有合格像素结构。轮廓、色块、像素层级及身份仍须实际查看，内容失真时通过 Image Gen 定向修复。

## 合成工程与共同时间轴

1. 优先编写可重复运行的本地工程或脚本。可用 Python/Pillow 等处理帧合成，由 FFmpeg 或等效编码器接收连续画面及最终音轨；也可接续已有可控制的动画工程。采用方式和依赖随作品保存。
2. 在素材清单中索引完整图片，在时间轴中引用采用素材标识和音频选用清单。镜头记录图层顺序、姿势图片、起止帧、锚点、整体位移及必要状态；角色身体不由部件拼装。
3. 以实际工程声音、动作和留白确定各段时序，上/下或上/中/下每段视频从零开始；保留段序、整体剧情位置与本段时间的对应关系，跨段道具、人物和环境状态延续。视觉帧使用 24 fps 的整数帧号，声音保留实际时间精度，本段字幕和触发事件映射到同一本段时间轴。偏移从采用声音和明确留白计算，避免舍入积累漂移，也不把上一段的字幕时间直接带入下一段。
4. 先渲染代表性样片，复用通过检查的镜头、素材与配置。按采用剧本的段序逐段核验并独立导出正式视频与字幕，不将所有段合成一个长片来替代分段交付；每段内部可按镜头渲染或流式编码，避免把全部 1080p 帧同时放入内存。
5. 保存实际采用的 `asset_manifest.json`、`timeline.json`、`render_config.json`，或已有工程的等效清单与配置，由 `project_state.json` 指向统一入口。记录各段标识/顺序、文件路径、段内时间与剧情对应、素材/音频版本、画布、采样、帧率、字体、运行方式、实际依赖和编码配置，使新聊天能逐段重建成片；不维护另一份重复的音频选用清单。

## 检查依据与适用边界

检查按 [阶段自查与放行](handoff-and-resume.md#阶段自查与放行) 在提交审阅、选用版本和下游交接前执行。先取得实际文件与对应版本，再检查并修复；下列证据分别记录，不能用一种检查替代另一种。已知可修复问题先处理，修复后检查受影响的上下文与依赖，再更新状态。

- 文本与资料：逐项核对采用剧本、录音稿和来源，未读取来源不能标记已核实。
- 图片：读取尺寸和透明通道，逐张查看采用结果，按 [肢体与头身动作检查](visuals-and-performance.md#肢体与头身动作检查) 核对手脚数量/归属、连接、关节、支撑和头身朝向，并查看实际换帧与合成预览；同组快速切换、叠加或检查图辅助定位漂移。阅读或展示镜头须核对人物视线、道具可读面、握持及镜头可见面的关系，不把提示词或数值相等当作角色身份、空间关系和画面美感已通过。
- 声音：探测时长、采样率、声道、削波、静音及转写覆盖。环境支持实际听音或音频理解时核验语气、读音和句尾；仅有转写与波形时记录技术结果，未试听的音色或情绪不标为听音通过。
- 视频：逐段读取编码规格、本段时间轴覆盖与全部剧情，分别执行完整解码检查；按镜头、关键动作、状态变化、字幕边界及段尾抽取画面查看。核对各段从零开始的字幕定时、播放顺序、段间状态/悬念承接与最后一段收束。完整解码、视觉抽查与完整播放是不同证据，分别记录覆盖范围；环境支持播放时完整观看并听音每段，再检查段间衔接。
- 封面：查看成品、缩略图与手机尺寸预览，核对实际剧情看点。评价依据创意、识别、美感和内容契合，不凭生成结果承诺点击率或完播率。

检查记录关联具体对象、版本、位置、方法与覆盖，保留发现问题、修复动作与复查结果。未核验项随成果交付说明并保存到进度索引；实际文件可作为标注清楚的检查稿先交付，只有满足本次完成条件时才标记阶段通过。工具限制不改变创作目标，也不许可将样片、占位素材或计划描述冒充正式成片。
