# 制作执行与能力边界

在检查工具、编写或接续工程、图片技术整理、动画合成、编码和组织检查时读取。只写剧本时执行文字、资料核验和保存工作，不要求预先配置媒体运行环境。保留 [主入口](../SKILL.md) 规定的工具分工与本次范围。

通过当前 Agent 的工具发现、连接器、文件或命令执行接口完成工作，接口名称与参数以实际暴露的能力为准。图片遵守 [即梦优先、Image Gen 备用与统一画布](canvas-and-image-routing.md) 的路由；Fish Audio MCP 按当前实测与用户要求仅用于音频，不纳入图片、视频或图生视频方案。执行这些规范的 Agent、客户端及工程运行方式不作平台限定。

## 能力与执行方式

| 环节 | Agent 的执行方式 | 完成依据 |
| --- | --- | --- |
| 选题与事实核验 | 理解用户主题，使用可用搜索及读取工具核验关键事实，保存来源和事实截止日期 | 实际读取的资料、准确的适用范围及完整剧本 |
| 剧本、录音稿与制作规划 | 生成和修订文本，提取台词，编排角色/场景/叙事段/镜头标识及依赖 | 已保存的采用版本、无漏句重复的交接记录 |
| 图片创作 | 按生图路由优先调用即梦，额度或必要能力不可用时用 Image Gen，生成或编辑完整背景、角色动作、道具、效果和封面 | 实际工具/模型、额度与报价依据、返回图片、查看结果和采用版本 |
| 画布整理 | 即梦结果复用已有节点，外部生成图片上传后创建图片节点，按参考图和镜头/动作帧排列并回读检查 | 作品画布链接、节点/资源与本地文件对应、布局及同步检查 |
| 图片技术整理 | 使用可用图片库或图片编辑工具读取尺寸/透明通道，按统一规则补画布、定位、格式整理及制作检查视图 | 同组尺寸与锚点数据、透明边缘及换帧检查 |
| 连续动画 | 按当前即梦双图首尾能力、报价与授权，仅生成当前片段画面与非人声音效/环境声 | 当前图片对/任务/片段对应、片内及首尾检查、实际音效；人物配音来自 Fish |
| 配音 | 通过 Fish Audio MCP 查询音色并提交生成文本，保存实际返回的声音 | 音色标识、正文/生成文本/音频对应及实际核验记录 |
| 动画与时间轴 | 编写、运行和修复本地合成工程，连续动画剪辑采用视频，翻页动画以完整图片换帧，两路统一声音、信息和状态时间轴 | 实际渲染的样片、叙事段、时间轴与可复用工程 |
| 排版与信息显示 | 使用字体和图片/排版工具制作字幕、标题、气泡、计数器及信息图层 | 核对文本、正确的数据和定时、清楚的实际预览 |
| 混音与编码 | 调用可用音频和编码工具，优先使用本地 FFmpeg/FFprobe 或已可调用的等效工具 | 音轨/配置、完整 MP4/SRT、实际规格与解码检查 |
| 验证与续作 | 读取文件和清单，查看画面，在环境支持时播放或理解音频/视频，记录证据并处理变更 | 当前版本、检查方式/覆盖范围、未核验项及下一步 |

无论采用哪种图片生成工具，角色一致性、精确构图和文字布局都须核验；不能把提示中的尺寸、锚点、调色板或保持条件当作已经满足。Image Gen 备用路径的能力说明见 [OpenAI 图像生成文档](https://developers.openai.com/api/docs/guides/image-generation)，实际调用仍以当前接口为准。

执行用户选择的 [动画路线](animation-routes.md)。翻页动画不要求连续视频接口，按多帧切换完成；连续动画缺少视频能力、额度或合格结果时，记录准确缺口和改走翻页动画的具体方案，由用户决定是否切换，不自动代选或缩减互动。共同文字与工程准备可继续，声音生成限定当前片段。

## 按阶段检查运行依赖

1. 图片工作先按 [生图路由](canvas-and-image-routing.md) 读取 `dreamina-canvas-cli` 技能、实时 CLI 能力及额度/报价条件，备用时读取 `imagegen` 技能；确认所用接口实际可调用。声音工作另检查 Fish Audio MCP 的音频接口及当前输入输出，不用即梦配音替代限定音色流程。Fish 的工具发现、额度检查与恢复均限定在音频工作内，不检查或接续其图片、视频、图生视频、自动口型或数字人任务。
   仅连续动画另检查视频模型的双图首尾约束、素材槽位、时长/分辨率、账号准入及报价；模型目录和登录不代表实际生成或额度已通过。不把图片模型、Image Gen 或 Fish 作为视频备用接口。
2. 使用可用的工作区依赖发现工具或 shell 检查 Python/Node、图片库、字体、媒体编码/探测工具及保存目录。优先复用当前环境可用运行时；不把某台机器的绝对工具路径写成 Skill 的固定要求。
3. 图片技术处理可使用 Python/Pillow、NumPy 或合适的等效库。绘画内容、美术修复和新动作内容继续通过所选生图工具创作；程序负责已规定的工程处理、排版和合成，不用几何占位图替代正式人物或场景。
4. 检查编码器及 H.264/AAC 支持、音频解码与中文字体的实际可用性。缺少依赖时按当前环境权限配置可用工具，或记录准确恢复条件；继续文字、图片、配音及可执行的独立工作。
5. 路线与当前画布确认后，仅用当前片段素材跑通剪辑/换帧、Fish 配音、音效、字幕及 1080p 输出。首片兼作样片，不强求十至十五秒；自查修复并经用户确认后才生成下一片段，不能凭首片确认批量放行。

## 图片生成与技术整理

投产前按 [事件与镜头连续性](story-continuity.md) 核对关键事件及必要镜头，保留合理省略的两端线索，先补缺失的执行、到达、结果/交接、回应或下一步关键画面，再补组内动作。把问题分为正文因果、镜头连接、姿势过渡或剪辑定时，针对缺口修复，不用增加同一动作的帧数替代叙事修订。

有意隐藏和稍后揭晓按 [多时间线揭示计划](dramatic-suspense-and-timelines.md) 检查，缺口定位到该呈现的位置；不能因当前镜头未揭晓就补图泄底。发声相关完整帧序列或视频在采用真实配音后确定嘴形、停顿和身体联动再投产，当前片段内无声任务可并行，不提前生成后片或临时拼嘴修补。

主剧本、分段稿、清单及路线确定后，按 [画布流程](canvas-and-image-routing.md#逐级确认与首尾帧先行) 建立共用参考，仅制作当前片段关键图并确认当前范围画布。连续动画再按 [连续动画](animation-routes.md#连续动画) 生成相邻状态片段，检查片内动作及实际首尾连接；翻页动画按 [上一帧微调](visuals-and-performance.md#标准参考图与上一帧微调) 将每个变化补至至少六张有效完整图片，检查全部采用图及相邻切换。六图下限仅适用于翻页动画，连续动画不额外补六张；两路都不能凭关键图齐全判连续动作通过。修复后复查依赖、同步本地与画布；按 [逐片确认](animation-routes.md#逐片生成与用户确认) 取得当前预览确认再投产下一片。

将两种来源的实际结果保存到作品目录，保留原始结果与工程副本。记录生成工具、画布节点及资源对应、实际宽高、透明通道、姿势组、基准版本、比例、锚点及来源。生成图片尺寸与工程画布不同并不等于可直接入工程；按整组统一规则整理并查看结果，不能逐帧紧裁、独立缩放或居中。

水彩形式的采样检查与审美检查分别进行：技术处理可统一画布、定位和透明边缘，简笔线稿、淡彩晕染、角色身份与跨帧纹理稳定仍须实际查看。不沿用旧像素工程的低分辨率画布和最近邻放大；采用保留柔和笔触与透明通道的统一高质量采样，检查白边、晕染破损、色块漂移及纸纹闪烁，内容失真时通过所选生图工具定向修复。

## 合成工程与共同时间轴

1. 优先编写可重复运行的本地工程或脚本。连续动画使用实际采用视频剪辑，翻页动画可用 Python/Pillow 等处理整图帧合成，由 FFmpeg 或等效编码器输出连续画面及最终音轨；也可接续已有可控制工程。保存实际源尺寸、帧率与统一导出转换，不能把低分辨率放大称为原生 1080p，也不把输出帧率转换算作补齐动作。
2. 素材清单索引完整图片或视频，时间轴引用采用素材及音频选用清单。连续动画记录视频源、版本、剪辑入出点及首尾连接，翻页动画记录图层、姿势图片、起止帧、锚点及整体位移；共用事件/状态与配音定时，不拼装身体部件。
3. 以实际工程声音、动作和留白确定各段时序，上/下或上/中/下每段视频从零开始；记录播放顺序、时间线/事件、故事时刻、历史状态及本段时间的对应。跨段按所属故事时刻承接，回忆不覆盖当下状态，同一事件回放不重复触发累计结果。视觉帧使用 24 fps 的整数帧号，声音保留实际时间精度，本段字幕和触发事件映射到同一本段时间轴。时长取声画、停顿及重叠的实际排布，不能只累加配音长度而删掉反应；偏移避免舍入漂移，也不把故事时刻或上一段字幕时间直接带入下一段。
4. 每次只渲染当前片段供审阅，复用已确认的参考及配置，当前片段用户确认后才生成后片。全部所需片段确认后，按采用剧本的段序逐段核验并独立导出正式视频与字幕，不将所有段合成一个长片来替代分段交付；每段内部可按镜头渲染或流式编码，避免把全部 1080p 帧同时放入内存。
5. 保存实际采用的 `asset_manifest.json`、`timeline.json`、`render_config.json`，或已有工程的等效清单与配置，由 `project_state.json` 指向统一入口。记录各段标识/顺序、文件路径、段内时间与剧情对应、素材/音频版本、画布、采样、帧率、字体、运行方式、实际依赖和编码配置，使新聊天能逐段重建成片；不维护另一份重复的音频选用清单。

## 检查依据与适用边界

检查按 [阶段自查与放行](handoff-and-resume.md#阶段自查与放行) 在提交审阅、选用版本和下游交接前执行。先取得实际文件与对应版本，再检查并修复；下列证据分别记录，不能用一种检查替代另一种。已知可修复问题先处理，修复后检查受影响的上下文与依赖，再更新状态。

- 文本与资料：逐项核对采用剧本、录音稿和来源，未读取来源不能标记已核实。
- 图片：读取尺寸和透明通道，逐张查看采用结果，按 [肢体与头身动作检查](visuals-and-performance.md#肢体与头身动作检查) 核对手脚数量/归属、连接、关节、支撑和头身朝向，并查看实际换帧与合成预览；同组快速切换、叠加或检查图辅助定位漂移。阅读或展示镜头须核对人物视线、道具可读面、握持及镜头可见面的关系，不把提示词或数值相等当作角色身份、空间关系和画面美感已通过。
- 声音：人物配音核对 Fish 来源，视频音效核对实际采用及分轨，去除误生人声时补齐受损音效；再探测时长、采样率、声道、削波、静音及转写覆盖。环境支持实际听音或音频理解时核验语气、读音和句尾；仅有转写与波形时记录技术结果，未试听的音色或情绪不标为听音通过。
- 视频：逐段读取编码规格、本段时间轴覆盖与全部剧情，分别执行完整解码检查；按镜头、关键动作、状态变化、字幕边界及段尾抽取画面查看。核对各段从零开始的字幕定时、播放顺序、段间状态/悬念承接与最后一段收束。完整解码、视觉抽查与完整播放是不同证据，分别记录覆盖范围；环境支持播放时完整观看并听音每段，再检查段间衔接。
  连续动画另检查全部采用生成片段的片内运动与每处拼接，逐帧检查动作、正常速度检查节奏；关键图全检和少量抽帧不能替代。检查方法及缺口见 [连续动画路线](animation-routes.md#连续动画)。
- 封面：查看成品、缩略图与手机尺寸预览，核对实际剧情看点。评价依据创意、识别、美感和内容契合，不凭生成结果承诺点击率或完播率。

连续性另按 [三层自查](story-continuity.md#自查与修复顺序) 检查实际事件顺序、全部镜头/场景/分段边界和组内动作。可用清单或工程检查定位缺失引用、时间重叠和不一致状态，但人物为何行动、省略能否理解、交接是否成立及回应是否有依据仍须查看实际呈现。完整解码或单组动作预览不能代替整场叙事检查；未具备播放/听音条件时准确保存检查覆盖与待核验范围。

检查记录关联具体对象、版本、位置、方法与覆盖，保留发现问题、修复动作与复查结果。未核验项随成果交付说明并保存到进度索引；实际文件可作为标注清楚的检查稿先交付，只有满足本次完成条件时才标记阶段通过。工具限制不改变创作目标，也不许可将样片、占位素材或计划描述冒充正式成片。
