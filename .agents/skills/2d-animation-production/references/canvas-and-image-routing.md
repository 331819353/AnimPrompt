# 即梦画布与生图路由

在分段剧本后整理待确认清单、规划首尾帧、生成或修复图片、整理画布与补帧时读取。完整主剧本、分段剧本、人物/场景/关键道具清单依次确认后才生成视觉素材；仅写剧本时无需创建画布或生成媒体。使用当前环境的 `dreamina-canvas-cli` 技能操作即梦；备用生图读取 `imagegen` 技能，命令、参数、模型和权限以技能及当前工具说明为准。

本流程的图片路由仅为“即梦优先 → Image Gen 备用 → 统一整理到即梦画布”。动画采用用户选择的 [连续动画或翻页动画](animation-routes.md)，生图工具切换不等于动画路线切换。连续动画的视频能力、额度与报价另行核对，Image Gen 仅负责图片。按用户实测结果，Fish Audio MCP 仅作为音频工具，不参与生图、修图、视频或图生视频；此前的 Fish 视觉尝试保留历史记录并停止接续。

## 逐级确认与首尾帧先行

清单同时登记 [多时间线与线索计划](dramatic-suspense-and-timelines.md)：同一人物/场景/关键道具在各故事时刻的版本、事件与呈现位置、线索铺垫及回收所需画面。人物身份不变，服装、年龄表现、环境和道具状态可按已确认版本不同；不因同名物件就复用错误时段图片。纯画外旁白仅需声音身份，不要求人物参考图。

跨线检查先按实际播放顺序定位观众信息，再沿各线真实时间核对因果和历史状态。有意隐藏的过程按计划在揭晓位置核对覆盖，当前未揭晓不等于漏图；当前片段确认范围内的线索画面须实际生成并检查，不能用后续计划代替当前图片。后续片段及未完成中间帧/声音单列待生成状态，逐片确认推进后补齐。画布以播放顺序为主，节点或清单标明时间线、事件/历史版本及线索身份，不按故事日期重排所有节点而打乱剪辑。

1. 核对主剧本、分段稿及路线选择，从采用版本提取人物、场景、道具及历史版本清单，按镜头规划关键状态和稳定片段编号。全局可先整理文字与共用参考需求，不提前投产后续片段专属图片或音视频。
2. 自查清单并请用户确认，可同时选择连续动画或翻页动画；未选择路线或清单待确认时不生成/上传视觉素材。新增设定或换路线更新对应决定。
3. 清单与路线确定后检查生图条件，建立合格共用标准参考，核对并复用作品画布；新建时保存实际身份、打开并交付链接。固定人物身份及各历史版本、空间、光照和镜头基准。
4. 按 [逐片确认](animation-routes.md#逐片生成与用户确认) 仅生成当前片段所需关键图。连续动画按镜头规划开始/过渡/结束，当前图片对先生成，后续专属终态图在前片确认后再生成；翻页动画先做当前动作的首尾及必要接触姿势。关键图依据同一基准编辑，不代表连续动作已完成。
5. 当前关键图逐张自查、本地保存并入画布，标明片段、状态与前后依赖。已确认片段保留采用版本，后续片段仅标文字计划/待制作；空节点、预留位置和未来计划不算已生成或通过。
6. 对照完整剧本计划核对整体覆盖，对当前片段及与已确认前片的承接检查实际画面：执行、接触/归属、结果、回应、线索及省略依据是否成立。未来片段按计划待生成，不为了全局画布一次齐全而提前生图，也不把未来缺口误标已补齐。
7. 自查修复后请用户确认当前范围关键图的造型、空间、状态与覆盖，记录片段/版本；确认后才投产本片段视频或中间帧。共用参考或前片画布确认不自动覆盖新增关键图。
8. 连续动画生成当前相邻图视频并检查片内运动；翻页动画按 [上一帧微调](visuals-and-performance.md#标准参考图与上一帧微调) 完成当前动作，每个变化至少六张有效完整图，12 帧例仍为首尾及十张中间图。先取得当前 Fish 配音再生成发声动态素材，本片段独立工作可并行。合成音效、配音和字幕，自查后提交实际片段，用户确认后回到第 4 步生成下一片段；不拆身体部件，不跨无关镜头续帧。

## 即梦优先与额度检查

生图、图生图编辑、问题帧修复和封面主视觉均按同一路由执行，来源与画布整理分别记录。动画图片/视频仅为当前片段保存与提交生成计划，不批量运行后续片段。

1. 首次使用及开始新批次前，检查 CLI 版本与 schema、登录状态、实际可用图片模型、所需图生图参考及透明输出等必要能力；区域取当前配置，不从对话语言推断。读取当前提供的额度信息，并仅对当前已获放行阶段的预期节点保存计划与取得权威报价，结合账号/模型权限及服务端准入判断能否执行。关键帧阶段不提前提交中间帧或视频，不用额外的试生成测试余额。
2. 若当前接口没有独立余额查询，记录“余额未直接核验”，使用可取得的报价与服务端结果判断；登录成功、能列出模型、报价成功或需要批准均不等于额度充足。未知金额也不能按零处理。
3. 即梦可用且满足本组完整图片、参考关系与输出需求时优先使用即梦。需要积分批准时展示本批内容、数量、报价与上限，复用已有明确且适用的授权；没有授权或价格超过授权上限时等待用户决定，不自动批准任意金额，也不静默降低数量或质量。

| 实际情况 | 处理 |
| --- | --- |
| 明确额度不足、额度已用尽，或所需模型权限/图片编辑能力不可用 | 记录具体依据与尚缺图片，使用 `imagegen` 技能生成或编辑这些图片，并导入同一画布；不自动购买额度或升级会员 |
| 仅缺少用户积分批准，或额度/价格尚不明确 | 保持待确认或待核验，说明具体缺口；不能记成额度不足，也不绕过待确认决定自动转到另一种付费调用 |
| 即梦生成已受理但等待超时、响应丢失或终态未知 | 使用原任务身份只读查询并恢复，先查明原结果，不重新提交，也不立即在 Image Gen 生成同一图片 |
| 画布登录、访问或上传暂不可用 | 可用的 Image Gen 工作先本地保存，登记待同步；画布恢复后补传并复查，不把画布故障误报为已完成导入 |
| 两种生图途径都不可用 | 保存已有合格图片、缺口和恢复条件，继续可独立进行的文字、声音或工程工作 |

同一动作组尽量保持同一生成工具。需要切换时复用标准人物图、镜头基准、首尾关键帧与上一合格帧，先核对切换后的图片与相邻过渡，再继续顺序生成；不能因切换改变人物、服装、背景、光照、画布、锚点、确认状态或规定图片数量。恢复即梦可用后，可在新的独立动作组重新选择，不在未完成的连续动作中来回切换。

## 统一导入与画布排列

1. 每张相关图片，包括基础图、动作帧、补帧、实际保留的候选与修复版本，使用独立图片节点展示；支持输出数量参数时每节点生成一张。即梦已有节点的结果直接整理，不重复上传同一结果。生成失败或尚无图片的节点如实记录状态，不能当作有效帧。
2. Image Gen 结果先保存实际文件，再通过当前 CLI 的资源上传能力登记为外部生成素材（当前契约为 `external_generated`），用返回资源创建带产物的图片节点。仅上传文件不会自动形成画布节点；回读确认节点选中了正确图片并可访问。记录实际生成工具，不把导入图伪装成即梦生成，也不为导入再次运行生图。
3. 画布上方安排人物、场景与关键道具参考，下方按段、事件、场景、镜头和动作组，以播放顺序表达事件链。连续动画排列开始/过渡/结束及增补关键图，视频生成后置于对应图片对旁并保存来源关系；翻页动画在首尾之间预留并插入中间帧，长序列可分行。离开/到达、结果/回应与有意省略保存对应，不用空白代替交代。按实际节点尺寸和父组坐标排列，回读并查看遮挡、重叠和可读性；预留位置不算已生成素材。
4. 节点标题标明人物/场景或镜头/动作、帧标识、版本及检查状态，详细记录仍保存到统一素材清单。待检查、已通过、待修复、停用版本清楚区分；整理位置不触发生图，不为改状态删除旧版本或重建整组。
5. 即梦下游生成优先引用已在画布上的来源节点，保留上一合格帧和所需人物/场景参考关系；回读核对引用与上游连线。Image Gen 编辑使用实际本地参考文件，来源关系记入清单；导入后不声称系统已自动建立原生生成连线。后续再由即梦编辑时可引用这些导入节点。
6. 补帧与新版本使用稳定的新标识，播放顺序独立记录，在画布相邻帧之间插入或为局部留出新行，避免批量重编号。修复后标明当前采用版本，并复查依赖它的后续帧；不要无记录地更换已被下游引用节点的选中产物。

## 本地同步、自查与恢复

- 即梦生成结果保存到作品目录；Image Gen 原始结果及工程副本同样保留。画布用于观察与协作，合成读取明确的本地采用版本，缩略图不能代替完整素材和逐帧检查。
- 复用 `asset_manifest.json` 或现有等效清单，记录清单/画布确认版本、路线、关键图/中间帧角色、缺口与补齐、实际顺序、工具/模型、参考版本、上一合格帧/目标尾帧、说明、本地路径、节点/选中资源及检查/采用/同步状态。连续动画另按 [视频记录](animation-routes.md#选择记录与切换) 关联相邻图片对、实际片段和剪辑，翻页动画保存有效图片数与帧序。任务保存恢复身份、报价及授权依据；`project_state.json` 只索引，不保存凭据或临时签名链接。
- 每批完成后核对清单、实际文件和画布节点一一对应，无漏图、重复帧、错误版本或布局遮挡；验证图片、动作连续性与画布同步分别记录。只完成上传、只有占位节点或仍有待同步项时，不能标记画布整理完成；继续本地独立工作时保留真实缺口。
- 恢复时先读取清单，再回读目标画布与原任务结果；只补传缺图、恢复未完成任务或修复指定帧。新增版本更新采用关系与后续检查范围，不因换工具或会话重启重复生成、重复花费或丢失原有画布。

配音按 [配音与音频](voice-and-audio.md) 使用 Fish Audio MCP，分段导出按 [动画与交付](animation-and-delivery.md) 使用可复用工程。连续动画需要真实生成的视频及画布对应；翻页动画不因采用画布而额外要求视频生成。两路均不要求即梦配音或时间轴节点。
