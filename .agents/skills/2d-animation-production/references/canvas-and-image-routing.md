# 即梦画布与生图路由

在分段剧本后整理待确认清单、规划首尾帧、生成或修复图片、整理画布与补帧时读取。完整主剧本、分段剧本、人物/场景/关键道具清单依次确认后才生成视觉素材；仅写剧本时无需创建画布或生成媒体。使用当前环境的 `dreamina-canvas-cli` 技能操作即梦；备用生图读取 `imagegen` 技能，命令、参数、模型和权限以技能及当前工具说明为准。

本流程的图片路由仅为“即梦优先 → Image Gen 备用 → 统一整理到即梦画布”。按用户实测结果，Fish Audio MCP 仅作为音频工具，不参与生图、修图、视频或图生视频；不查询其图片/视频模型与报价、不上传视觉参考或提交视觉生成任务，也不将订阅升级作为这一路由的恢复条件。此前的 Fish 图生视频尝试保留为历史记录并停止接续。

## 逐级确认与首尾帧先行

1. 先核对完整主剧本与分段剧本的两项确认。分段剧本确认后，从采用版本提取人物、场景和关键道具清单：稳定标识、人物身份/年龄/外形/服装、场景结构与机位需要、道具外观/用途/归属/状态及关联段/场景。列出实际需要的关键变化、起止状态、互动对象和计划图片数量，复用已有设定，不强制生成全套多视图或无关图片。
2. 自查清单对分段正文的覆盖，修复遗漏或冲突后请用户确认。清单待确认时仅进行文字整理、资料核验和只读工具检查，不生成或上传视觉素材。确认后的清单作为参考图、首尾帧和画布整理的依据；新增人物或实质改变造型、场景/关键道具时更新相关确认。
3. 清单确认后按下方路由检查生图条件，先生成并检查标准人物图与必要场景/道具参考，固定身份、比例、服装、空间、机位、光照和画布/锚点。核对原作品画布并优先复用；没有对应画布时创建一个供各段共用的作品画布，保存实际身份与链接，打开并交付链接。
4. 为每个关键变化先生成首帧与尾帧，分别表现明确的起始与结束状态；两图依据同一参考和机位，动作、道具归属及环境状态符合已确认剧情。尾帧可从首帧编辑到目标姿势，作为尚未补间的规划关键帧，不要求此时两图差异很小。所需关键接触、转折姿势也可先建立关键图，但不将这些稀疏图片当作连续动作已完成。
5. 将标准参考、首尾帧和已有关键图统一放入画布，按段/场景/镜头/动作组排列，明确首帧、尾帧和中间待补位置。每张图自查后入画布并保存本地对应；当前只有首尾两图的变化标记为“关键帧阶段”，不能标记为完整动作组已通过。
6. 对照全部分段正文、关键变化表及 [事件链](story-continuity.md) 检查缺失画面：某段/场景、变化首尾、启动执行、省略两端、到达、接触/交接结果、人物获取信息与回应、下一步和必要转场是否有承载。按事件顺序串看画布，核对各组之间的时间、位置、物件归属与任务状态；先补叙事关键画面，再补组内姿势，不能只看每组首尾。清单记录具体缺口、承载镜头、补充图片与检查结果，合理省略不强制补全路程，空节点或未生成计划不算补齐。
7. 将自查和补齐后的首尾帧画布交用户确认造型、空间、剧情覆盖及动作起止。确认后才开始中间帧生成；用户的文本清单确认不自动代表实际视觉成果已确认，等待期间不批量补间。
8. 根据已确认首尾帧及必要关键姿势规划动作路径和过渡，再按 [上一帧微调](visuals-and-performance.md#标准参考图与上一帧微调) 以播放顺序逐帧生成、检查和补帧。先完成代表性样片的动作组，样片确认后扩展其他组。完整变化序列至少六张有效不同图片，首尾满足条件时计入；12 帧举手例先做 `F01`、`F12`，再补 `F02` 至 `F11`，总数仍为 12。配音与录音稿仅在各自前提满足时并行，最终嘴形与定时依据实际声音核定。

## 即梦优先与额度检查

生图、图生图编辑、问题帧修复和封面主视觉均按同一路由执行，生成来源与画布整理分别记录。

1. 首次使用及开始新批次前，检查 CLI 版本与 schema、登录状态、实际可用图片模型、所需图生图参考及透明输出等必要能力；区域取当前配置，不从对话语言推断。读取当前提供的额度信息，并仅对当前已获放行阶段的预期节点保存计划与取得权威报价，结合账号/模型权限及服务端准入判断能否执行。首尾帧阶段不提前提交中间帧，不用额外的试生成测试余额。
2. 若当前接口没有独立余额查询，记录“余额未直接核验”，使用可取得的报价与服务端结果判断；登录成功、能列出模型、报价成功或需要批准均不等于额度充足。未知金额也不能按零处理。
3. 即梦可用且满足本组完整图片、参考关系与输出需求时优先使用即梦。需要积分批准时展示本批内容、数量、报价与上限，复用已有明确且适用的授权；没有授权或价格超过授权上限时等待用户决定，不自动批准任意金额，也不静默降低数量或质量。

| 实际情况 | 处理 |
| --- | --- |
| 明确额度不足、额度已用尽，或所需模型权限/图片编辑能力不可用 | 记录具体依据与尚缺图片，使用 `imagegen` 技能生成或编辑这些图片，并导入同一画布；不自动购买额度或升级会员 |
| 仅缺少用户积分批准，或额度/价格尚不明确 | 保持待确认或待核验，说明具体缺口；不能记成额度不足，也不绕过待确认决定自动转到另一种付费调用 |
| 即梦生成已受理但等待超时、响应丢失或终态未知 | 使用原任务身份只读查询并恢复，先查明原结果，不重新提交，也不立即在 Image Gen 生成同一图片 |
| 画布登录、访问或上传暂不可用 | 可用的 Image Gen 工作先本地保存，登记待同步；画布恢复后补传并复查，不把画布故障误报为已完成导入 |
| 两种生图途径都不可用 | 保存已有合格图片、缺口和恢复条件，继续可独立进行的文字、声音或工程工作 |

同一动作组尽量保持同一生成工具。需要切换时复用标准人物图、镜头基准、首尾关键帧与上一合格帧，先核对切换后的图片与相邻过渡，再继续顺序生成；不能因切换改变人物、服装、背景、光照、画布、锚点、确认状态或规定图片数量。恢复即梦可用后，可在新的独立动作组重新选择，不在未完成的连续动作中来回切换。

## 统一导入与画布排列

1. 每张相关图片，包括基础图、动作帧、补帧、实际保留的候选与修复版本，使用独立图片节点展示；支持输出数量参数时每节点生成一张。即梦已有节点的结果直接整理，不重复上传同一结果。生成失败或尚无图片的节点如实记录状态，不能当作有效帧。
2. Image Gen 结果先保存实际文件，再通过当前 CLI 的资源上传能力登记为外部生成素材（当前契约为 `external_generated`），用返回资源创建带产物的图片节点。仅上传文件不会自动形成画布节点；回读确认节点选中了正确图片并可访问。记录实际生成工具，不把导入图伪装成即梦生成，也不为导入再次运行生图。
3. 画布上方安排人物标准图、场景与关键道具参考，下方按叙事段、事件、场景、镜头和动作组分区，以实际播放顺序表达事件链。先放每组首帧与尾帧，在两者之间预留补间位置；后续插入关键姿势和中间帧，长序列可分行并标明衔接。跨组离开/到达、结果/回应与有意省略保存明确对应，不用空白间距代替交代。按实际节点尺寸和父组坐标安排间距，回读位置并查看画布，核对顺序、遮挡、重叠与可读性；预留位置不计作已生成图片。
4. 节点标题标明人物/场景或镜头/动作、帧标识、版本及检查状态，详细记录仍保存到统一素材清单。待检查、已通过、待修复、停用版本清楚区分；整理位置不触发生图，不为改状态删除旧版本或重建整组。
5. 即梦下游生成优先引用已在画布上的来源节点，保留上一合格帧和所需人物/场景参考关系；回读核对引用与上游连线。Image Gen 编辑使用实际本地参考文件，来源关系记入清单；导入后不声称系统已自动建立原生生成连线。后续再由即梦编辑时可引用这些导入节点。
6. 补帧与新版本使用稳定的新标识，播放顺序独立记录，在画布相邻帧之间插入或为局部留出新行，避免批量重编号。修复后标明当前采用版本，并复查依赖它的后续帧；不要无记录地更换已被下游引用节点的选中产物。

## 本地同步、自查与恢复

- 即梦生成结果保存到作品目录；Image Gen 原始结果及工程副本同样保留。画布用于观察与协作，合成读取明确的本地采用版本，缩略图不能代替完整素材和逐帧检查。
- 复用 `asset_manifest.json` 或现有等效清单，记录清单与画布的确认版本、关键变化与首帧/尾帧/其他关键图/中间帧角色、缺失与补齐结果、计划和实际帧序、工具/模型、参考版本、上一合格帧及目标尾帧、生成说明、本地路径、画布/节点/选中资源身份、检查/采用/同步状态。即梦任务另保存恢复所需提交/操作身份、报价与授权依据；`project_state.json` 只索引这些记录。认证凭据、积分令牌和临时签名链接不写入作品状态。
- 每批完成后核对清单、实际文件和画布节点一一对应，无漏图、重复帧、错误版本或布局遮挡；验证图片、动作连续性与画布同步分别记录。只完成上传、只有占位节点或仍有待同步项时，不能标记画布整理完成；继续本地独立工作时保留真实缺口。
- 恢复时先读取清单，再回读目标画布与原任务结果；只补传缺图、恢复未完成任务或修复指定帧。新增版本更新采用关系与后续检查范围，不因换工具或会话重启重复生成、重复花费或丢失原有画布。

配音仍按 [配音与音频](voice-and-audio.md) 使用 Fish Audio MCP，动画合成与分段导出仍按 [动画与交付](animation-and-delivery.md) 使用可复用工程。采用画布不额外要求即梦视频、配音或时间轴节点。
