# 阶段衔接与续作

本文件管理作品的范围、采用版本、阶段交接和恢复。具体创作方法见 [剧本创作](scriptwriting.md)、[视觉与表演](visuals-and-performance.md)、[配音与音频](voice-and-audio.md)、[动画与交付](animation-and-delivery.md) 及 [封面与发布](covers-and-publishing.md)。按本次任务读取有关部分。

## 开始项目

1. 从当前请求确定模式、目标成果和修改范围。复用用户指定的作品目录；未指定时在工作区建立有辨识度的作品目录。多个作品分别记录，输出与 Skill 源码分开。
2. 检查实际存在的剧本、素材、工程及 `project_state.json`。用户指定的剧本优先；存在多个候选且无法判断采用版本时，只询问这一必要信息，不自行混用多个剧本。
3. 只写剧本和从主题到成片模式按 [剧本创作](scriptwriting.md) 安排默认信息。已有剧本制作动画模式检查角色、分场、对白、动作和必要旁白是否足够制作，理解参考资料及故事规则；不为了套用主题写作方法重写用户剧本。
4. 沿用已有记录、确认与明确偏好，记录本次范围和版本。常规细节与自检自主完成；按下方节点与用户确认方向、剧本和样片，不把授权制作整片等同于已确认尚未展示的内容。用户明确指定采用的已有剧本可视为该版本已确认，不重新开题；发现影响制作的剧情疑问或需要改写时仍须提出。

## 用户沟通与确认

| 节点 | 提供给用户判断的成果 | 确认后的推进范围 |
| --- | --- | --- |
| 选题与故事方向 | 核心问题、讲述价值与范围、必要事实及类比边界；人物愿望、冲突、因果、关键转折、结尾和代表性对白 | 按确认方向完成分场剧本；方向尚未明确时可先讨论选题，再讨论故事方案 |
| 完整剧本 | 已自行审读的完整版本、相关来源及仍需取舍的疑问；请用户判断剧情、人物、对白和结尾是否合适 | 整理录音稿与镜头、生成代表性图片和试音、制作样片 |
| 代表性样片 | 约十至十五秒的实际动画，附必要的角色/场景小样与试音，展示画风、音色、对白节奏、表演和字幕 | 复用确认的基准，批量生成其他章节素材并制作全片 |

每个节点先完成可审阅的成果，并执行下方 [阶段自查与放行](handoff-and-resume.md#阶段自查与放行)，修复可自行判断的错误后再提供文件或预览及明确的确认问题；不能只展示计划就请用户批准，也不能等用户指出明显缺陷才检查。样片选择能体现人物说话、关键情绪与动作的段落。其他重要创作疑问随发现及时提出，不拖到最终交付才说明。自检能解决的细节直接修复，不把所有技术操作变成确认节点。

确认按实际内容与版本记录。用户已明确选择方向、指定采用剧本或认可样片时沿用，不反复询问；局部修改只确认受影响的创作决定。用户明确授权本次全权创作、跳过特定节点或不经审阅直接制作时，记录相应授权及范围；未回复、文件已生成、技术自检通过或笼统的“做成片”均不能代替默认节点的内容确认。

等待必要确认时暂停依赖该决定的写作、媒体生成或批量制作，保存成果与未决事项；继续可独立进行的资料核验、文件整理及工具检查。收到反馈后先修订并说明变化，再按确认范围推进。涉及主题结论、主线、人物动机、结尾或样片基准的实质变更，更新对应确认状态；普通措辞和技术修复沿用既有确认。

## 阶段自查与放行

自查是每个阶段采用和交付前的必做工作，用户明确跳过创作审阅不等于跳过质量检查。检查已保存的实际成果及其上下文，按下表确定本次范围；只写剧本无需检查尚未制作的音视频，局部修改复查受影响部分及其真实依赖。

| 阶段 | 必须覆盖的对象与检查重点 |
| --- | --- |
| 选题与故事方向 | 核心问题、事实依据、类比边界、人物愿望与冲突、关键因果和拟定结尾；主动检查是否存在误导、动机缺口或显然可行却未解释的解决办法，具体标准见 [剧本创作](scriptwriting.md) |
| 完整剧本 | 逐场、逐段检查完整正文，再连贯审读全篇；核对动机、因果、时间/数量/规则一致、伏笔与结尾、自然对白和对话回应，按 [剧本自查](scriptwriting.md#交付前自行审读并修改) 修订 |
| 录音稿与配音 | 对照采用剧本核对全部台词段的角色、顺序、覆盖、正文/生成文本版本、音色和选用结果；检查漏句、重复、说明误读、读音、句尾截断、标签效果及声音连续性，技术/转写/听音分别执行和记录，见 [配音与音频](voice-and-audio.md) |
| 图片与完整姿势 | 实际查看每张采用图片；核对角色/场景身份、画风、画布/锚点、手脚数量与连接、头身朝向、握持/支撑、视线与道具可读面、空间/透视/遮挡，见 [视觉与表演](visuals-and-performance.md)；缩略图或抽样不能替代逐张检查 |
| 动作段与样片 | 查看每组相邻姿势、关键变化和循环首尾，再检查实际合成；核对多肢/重影、滑步/穿透、头身转向、道具与环境状态、嘴形/停顿、字幕和音效定时，具备条件时正常速度与慢速播放，不能用合格单图替代动作检查 |
| 章节及全片 | 检查全部章节及连接处，核对剧情、素材与声音版本、状态延续、章节偏移、缺失/重复/空白、音画同步与完整尾声；有播放能力时连贯观看并听音，修复局部后重新核对相关衔接，不能用样片通过代表全片通过 |
| 封面与发布文案 | 查看三种比例的实际封面及小尺寸预览，核对文字、构图、角色/画风与实际成片、标题和介绍的准确性、反转与结尾是否被不当泄露，见 [封面与发布](covers-and-publishing.md) |
| 最终导出与交付 | 完整解码正式 MP4，核对规格、时长与章节覆盖；检查 SRT 正文/顺序/边界、画面和声音起止、交付文件与清单/工程引用；检查对象必须是修复后的最终导出版本，见 [动画与交付](animation-and-delivery.md) |

执行“取得实际成果及版本 → 检查 → 记录具体问题 → 修复 → 复查 → 判定是否可交接”。先按创作要求核对，再从听众、观看者或对话对象的角度重新审读/查看，尤其检查上一轮修改是否引入了新的因果、空间、数量或定时错误。自动检查可定位格式、覆盖、规格和时间问题，语气、画面、动作与连续性仍须用相应实际检查核验。

每条问题关联成果编号/路径/版本及具体段落、姿势、镜头或时间位置，记录问题、检查方法与覆盖、修复动作、新版本和复查结果。复用已有检查记录，由 `project_state.json` 指向统一入口，不另建重复清单；简短作品也须保存相应自查结论。下游依赖变更时按 [变更传播与复查](handoff-and-resume.md#变更传播与复查) 更新检查有效范围。

发现可解决的内容或制作错误，先自行修复再提交；尚有影响本阶段交接的已知错误时，不能标为 `passed` 或让依赖它的下游采用。需要用户决定的创作取舍单列为未决事项，附具体影响与建议；工具/素材不足导致未完成的检查单列为待核验，说明缺口与恢复条件。文件可作为明确标注的检查稿交付，但不能称为合格定稿。对用户简述检查覆盖、主要修复和仍待判断/核验的事项，无须展示冗长的逐项自检过程。

## 作品进度记录

`project_state.json` 是作品的进度与依赖索引；台词、音频选用、视觉素材及时间轴各保留自己的详细记录，进度索引引用其路径和版本，避免重复维护一份正文或音频清单。

按实际工作填写以下信息，字段可以扩展，不为未执行工作伪造结果：

| 信息 | 保存内容 |
| --- | --- |
| 项目标识与范围 | 稳定的 `project_id`、作品名、当前模式、本次目标、明确偏好、输出目录、`visual_style` 及采用规范 |
| 采用剧本 | 实际路径、版本及可用的内容指纹；适用的主题范围、事实截止日期、来源和结尾意图随剧本保存，区分已交代的结果与保留的问题 |
| 用户确认与未决事项 | 各节点的成果路径/版本、用户决定及对话依据、适用范围、待回答的问题与影响；明确跳过节点时保存授权依据 |
| 阶段进度 | 当前阶段、检查状态、采用成果、所依赖的上游版本、未完成项 |
| 成果索引 | 相对作品目录的路径、成果编号、版本、依赖及实际检查记录位置 |
| 交接与恢复 | 角色/分场/章节对应记录、音频和素材清单、工程与时间轴入口、下一步、工具或素材缺口 |
| 变更记录 | 修改缘由、受影响范围、仍可复用成果、需更新或复查的部分、更新时间 |
| 实际运行与检查 | 当前工具/运行时、字体、图片与编码依赖、工程运行入口；各阶段自查记录入口、对象/版本/位置、方法与覆盖、发现问题/修复版本/复查结果、仍需处理或待核验项；技术/画面/转写/听音/连续播放分别记录 |

阶段可以使用 `script`、`manuscript`、`visuals`、`voice`、`timeline`、`animation`、`mix_subtitles`、`covers_copy`、`export_qa`。阶段状态统一为 `not_started`、`in_progress`、`passed`、`needs_recheck` 或 `blocked`；状态表示实际进度，阶段下记录已通过的章节或素材，允许局部制作与局部复用。

- `passed`：该阶段当前采用成果已满足本次目标的交接条件，且阶段自查与问题复查已完成、检查依据仍有效；区分文件生成、技术核验和感知检查，有影响交接的已知错误或必需检查尚未执行时不能标记为已通过。
- `needs_recheck`：依赖的内容或配置发生变化，需要更新或重新核验；记录具体范围，无须否定整个阶段的所有素材。
- `blocked`：该阶段缺少必要输入、工具或素材；记录恢复条件，其他独立阶段仍可推进。
- “本次请求完成”与“整片完成”分别记录。只写剧本完成后，动画阶段仍是尚未执行，不能把它们标为通过。

用户确认单独用 `user_review` 记录，节点可用 `direction`、`script`、`sample`，状态为 `pending`、`confirmed`、`waived` 或 `needs_reconfirm`。记录关联版本、决定与依据；`waived` 仅用于用户明确授权跳过的范围。技术与内容自检结果仍保存在阶段检查中，不能自动写成用户已确认。等待确认时记录所暂停的依赖和下一步，不误报为工具故障或整片完成。

首次仅写剧本时，记录项目范围、剧本版本与阶段、有关用户确认与未决事项、必要角色与分场标识及下一步即可。进入动画阶段再补充对应清单和工程信息，不预填虚假的音色、素材路径或调用日志。工程已有格式足以表达这些信息时可复用，在索引中指向它们。

## 稳定编号与版本

角色、分场、章节、镜头、台词段及复用素材使用稳定标识，建立必要的对应关系。作品内首次分配后不因插入、删除或调整顺序而给所有旧成果重新编号；播放顺序单独记录。新增内容使用未占用标识，删除内容标记停用，旧标识不分配给另一内容。显示名称可以改，标识继续关联原对象。

已有完整编号时沿用并核对唯一性。只有在动画制作需要时才建立镜头、素材等标识；单纯写剧本不扩张成整个制作工程。台词段编号、生成文本与音频版本的细则见 [配音与音频](voice-and-audio.md)。

“采用版本”表示已满足相应自检与用户确认条件、用于下游的版本；待审阅成果单独标明，不因自检通过就登记为已确认。生成新版本保留原稿、原始媒体和必要工程副本；用清楚的文件名或工程版本机制区分候选与采用结果。参考文件是制作规范，作品的剧本、记录与工程才是实际成果。

## 阶段交接条件

| 交接 | 下一阶段需要什么 | 校验与完成边界 |
| --- | --- | --- |
| 主题 → 剧本 | 经用户确认的选题与故事方案、核心问题、范围、普通观众能理解的生活关系及必要事实依据 | 方向确认有记录；剧本满足生活质感、自然对白、因果、类比边界、反转与结尾要求，关键事实与来源可核对 |
| 剧本 → 录音稿及镜头构思 | 唯一已确认的采用剧本、角色/分场标识、对白与动作区分、必要旁白、相关来源 | 剧本完整保存，内容确认或用户明确授权跳过的依据可核对；明确需要读出的内容，现实对应说明和来源列表不自动变成台词 |
| 录音稿 → 图片及配音 | 全章节正文、稳定台词段编号、分场对应、表演说明、生成文本与生成清单 | 不漏句、不重复；标签与导演说明分开；录音稿完整交付后先并行推进样片所需图片和声音，其余章节在样片确认后展开 |
| 图片 → 合成 | 完整姿势图片或完整镜头动作图片、选中的形式/空间设定、姿势组基准与统一画布/比例/锚点、遮挡关系、版本及来源 | Image Gen 结果实际查看，同组完整帧通过尺寸和换帧对齐校验，已查看实际图片合成预览；像素形式另检查逻辑网格 |
| 配音 → 时间轴 | 已生成并完成可执行核验的选用声音、`audio_manifest.json`、工程文件及处理后时长 | 唯一选用与分片顺序明确，真实时长、正文覆盖及各项检查状态可核对；未试听的语气或读音继续标记待核验。可先制作可用章节，全片导出前须覆盖全部章节 |
| 时间轴 → 样片及章节动画 | 采用声音与图片、统一时间轴版本、关键动作/状态/信息/嘴形/字幕/声层的对应位置 | 先制作有代表性的约十至十五秒样片并修复，提交用户确认后再批量展开章节；已确认且通过检查的基准可复用，整片完成仍须覆盖全部章节 |
| 全片 → 封面复核、导出及交付 | 完整章节、混音、字幕、封面与文案、可复用工程、实际检查记录 | 对照实际成片复核封面与文案，完成规格/解码/画面及当前可执行的播放检查；缺失部分继续修复，未能核验项随成果明确交付 |

制作阶段在完成成果、选择新版本、发生重要变更或暂停工作时更新索引。记录完成后明确下一个可执行动作与所需文件，使新聊天能从作品目录恢复。

## 变更传播与复查

先定位修改内容的真实依赖，再更新涉及的成果并标记复查范围。复用不受影响且仍通过检查的部分；必要的后续连续性和定时复查不能省略。

| 变更 | 需要检查的依赖 |
| --- | --- |
| 台词、旁白或剧情顺序 | 录音稿正文/生成文本、相关配音、镜头和表演、状态/信息、字幕、章节及全片时间映射 |
| 音色、标签、读音处理、配音选用或声音编辑 | 音频版本/选用清单、实际时长、嘴形/动作/停顿、字幕、混音及后续偏移 |
| 角色造型、场景结构、机位、道具状态或动作结果 | 有关图片/姿势、视线与道具可读面/可见面、遮挡/接触、连续性记录、后续状态与数据展示、相关封面 |
| 视觉形式切换 | 新形式的角色/场景参考、有关完整动作图片、排版、采样和输出配置、封面及检查记录；剧情和配音内容未变时复用已核验声音，重新核对受影响的表演与时间轴 |
| 结尾意图或尾声情节 | 相关剧本、伏笔、录音稿/配音、尾声画面与定时、完整结尾检查、封面及发布文案 |
| 逻辑画布、姿势组基准、角色比例/锚点、像素网格、放大倍率或工程定位 | 同组完整动作图片的规格与对齐、有关图层、镜头、信息文字、封面落版、合成及导出配置 |
| 镜头时长、留白、段落顺序或无声动作 | 时间轴、状态变化/信息/音效、章节偏移、嘴形、字幕、混音及导出 |
| 封面创意或发布标题 | 三种比例的识别、所选风格、故事看点和实际成片对应；若仅调整封面，不自动重做音频 |
| 事实依据、数量定义或类比关系 | 剧本中相应表达、画面信息及状态、适用的录音稿/配音/字幕与发布文案 |

时间轴变化从受影响位置重新核对后续偏移。时间增加不等于故事中发生了新动作；数据不因重复播放或镜头调整重复累计。仅改显示名称时更新引用；文本或事实变化则更新真正使用它的内容。具体声音定时见 [配音与音频](voice-and-audio.md)，状态推理见 [视觉与表演](visuals-and-performance.md)。

## 恢复与继续制作

1. 读取 `project_state.json` 和最新请求，检查采用剧本、关键清单、工程与文件是否实际存在，核对版本、依赖、已有检查与用户确认依据，继续处理未决问题。索引与实际文件不一致时，以核对结果修正记录，不把文件存在等同于已经通过检查或用户确认。
   跨聊天或环境恢复时按 [制作执行与能力边界](production-execution.md#按阶段检查运行依赖) 重新确认工具和工程入口。认证、返回 URL、运行时路径或工具参数变化不能由旧记录替代核对；保留可用的本地文件和通过检查的成果。
2. 项目没有进度索引时，从实际剧本、音频清单、素材和工程重建最小索引。保留可靠编号、音色和素材；缺失的检查标记待核验，不宣称旧成果已经播放或检查。
3. 将用户新要求合并到原目标：只改某个部分时限定范围；从已完成剧本转为制作动画时接收已确认的采用剧本；继续全流程时从下一未完成阶段接续。沿用记录中的 `visual_style`；明确切换形式时更新依赖、有关确认与复查范围，不混用旧形式的素材及采样配置。
4. 遇到未确定结果的媒体调用，先查询已有响应、任务和文件，再决定是否重试。修复缺失或失败部分，保留通过检查的结果，不把恢复等同于全部重生成。
   恢复图片工作时核对同组完整姿势的实际尺寸、基准、比例和锚点；旧工程若使用独立嘴部或肢体片段，改为完整姿势图片并更新关联换帧配置，不把旧部件标为符合当前规范。
5. 依赖临时不可用时记录阶段缺口与恢复条件，继续可执行的独立工作。恢复后核验实际结果，再进入相应下游阶段；没有真实声音时可继续静态图片及镜头构思，最终嘴形与字幕定时留待声音核定。
6. 更新记录并交付本次实际成果和剩余事项。要求成片时持续制作；明确暂停或只完成一个阶段时保存进度，在该边界停止。已导出的旧版本可保留，最终交付清楚指向唯一当前正式成片。
