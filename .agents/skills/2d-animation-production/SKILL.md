# 二维动画创作与制作

将主题转化为有事实依据、生活质感和启发性的原创情景剧，并按用户要求选择日系唯美像素或讽刺手绘卡通形式，制作二维有限动画。支持完整创作，也支持从已有剧本或工程接续制作。

本 Skill 面向所有读取并执行这些规范的 Agent，不限定模型、客户端或执行平台。文中的“Agent”均指当前执行者；按本次任务范围检查工具、权限和运行依赖，只写剧本时无需具备媒体生成与编码能力。

执行本 Skill 的 Agent 负责理解、写作、制作规划、工具调用、代码执行和实际成果检查；Image Gen 负责图片创作，Fish Audio MCP 负责配音，本地合成与编码工具负责动画工程和导出。各阶段以当前执行环境可调用的工具、已保存文件及实际检查为依据。

## 选择本次范围

| 用户目标与现有输入 | 执行模式 | 完成边界 |
| --- | --- | --- |
| 根据主题写故事、写剧本；只提供主题且未要求成片 | 只写剧本 | 完整剧本、适用的来源与类比边界、交接记录 |
| 将用户指定的已有剧本制作成动画 | 已有剧本制作动画 | 从剧本交接开始，完成成片、字幕、封面、发布文案及工程 |
| 根据主题创作并做成完整动画或视频 | 从主题到成片 | 剧本创作与动画制作全流程 |
| 继续已有工程、修改某一部分或修复问题 | 按原模式续作或局部修改 | 用户本次指定的成果与受影响部分的复查 |

以用户最新要求确定范围。明确只写剧本、只做封面或只修复某个镜头时，完成对应部分；要求成片时按确认后的方向持续完成整片。常规细节自行安排；话题是否适合、剧情是否符合用户意图及影响主线的疑问，按下方沟通节点与用户讨论。

## 选择视觉形式与结尾

每个作品选择一种视觉形式，场景、角色、动作图片、特效、封面与导出沿用同一规范：

| 形式 | 适合的表现重点 | 读取规范 |
| --- | --- | --- |
| 日系唯美像素，`japanese-pixel` | 精细像素色块、协调光影、完整生活场景及清楚的情境表演 | [像素形式](references/style-japanese-pixel.md) |
| 讽刺手绘卡通，`satirical-cartoon` | 简洁线条、强表情、对比构图、荒诞隐喻和反讽余韵 | [卡通形式](references/style-satirical-cartoon.md) |

用户明确指定视觉形式时采用对应形式；续作沿用已记录的选择；全新作品未指定时默认日系唯美像素。将 `visual_style` 和采用规范保存到作品进度记录，只读取选中的形式规范，不把像素网格和卡通平滑线条混用于同一作品。

结尾独立于画风选择，可以完整收束、留下后续选择，或形成循环反讽的余韵。开放结局仍交代关键因果与已经发生的结果，留下有依据的判断或未来走向；不能以突然截断剧情代替完整作品。按 [剧本的结尾设计](references/scriptwriting.md#结尾设计与观众参与) 构思，在进度记录中保存结尾意图。

## 开始与按阶段读取

首先检查用户指定的输出目录和已有成果，按 [阶段衔接与续作](references/handoff-and-resume.md) 的“开始项目”确定采用的剧本与当前进度。新作品的成果保存到用户指定目录，未指定时使用当前工作区下清楚命名的作品目录；不要写入 Skill 源码目录。

只读取当前阶段需要的参考文件。跨阶段时读取下一阶段的要求，续作或修改时补读对应的恢复与变更规则。

| 阶段 | 读取文件 | 用途 |
| --- | --- | --- |
| 主题分析、事实核验、故事构思、剧本创作或修订 | [剧本创作](references/scriptwriting.md) | 生活类比、反向思考、因果、人物、结尾及剧本交付 |
| 工具就绪、编写合成工程、选择运行依赖或组织实际检查 | [制作执行与能力边界](references/production-execution.md) | 按阶段发现工具、图片技术整理、程序合成、检查依据及恢复 |
| 接收剧本、阶段交接、恢复进度或处理变更 | [阶段衔接与续作](references/handoff-and-resume.md) | 采用版本、稳定编号、成果依赖、完成条件与续作 |
| 镜头、场景、角色、图片、表演与信息可视化 | [视觉与表演](references/visuals-and-performance.md) 及选中的形式规范 | Image Gen、完整动作图片、有限动画与连续性 |
| 录音稿、音色、声音标签、配音核验或混音 | [配音与音频](references/voice-and-audio.md) | Fish Audio MCP、正文与生成文本、音频选用及声音时间映射 |

## 推进流程

只写剧本：主题与重点问题、必要事实核验 → 选题与故事方向确认 → 完整分场剧本 → 自行审读与修订 → 交付审阅、按反馈修改 → 保存成稿及交接记录。交付完整剧本，完成后停在本次范围内。

已有剧本制作动画：核对指定剧本、版本及内容确认情况 → 完整分章节录音稿与生成清单 → 检查媒体工具和运行依赖 → 静态小样、完整动作小组与角色试音 → 图片及配音核验、统一成片时间轴 → 跑通并确认代表性动画样片 → 复用合格成果制作全部章节 → 混音、字幕、封面与发布文案 → 导出、实际检查及交付。

从主题到成片：先与用户确定选题与故事方向，完成剧本并取得内容确认，再衔接动画制作。阶段交付用于展示可审阅成果、收集反馈和保存进度；满足相应确认与交接条件后，在用户已授权的范围内继续推进，待核验项按能力边界记录。

录音稿完整交付后，图片与配音可并行推进；先用小范围成果跑通生成、整理、声音定时和实际合成，样片经用户确认后再扩展到全部章节。真实配音核验后确定最终表演、嘴形和字幕定时。封面创意可提前探索，最终标题、封面和发布文案须对照实际成片复核。续作优先复用当前有效成果，变更按依赖关系传播。

## 用户沟通与确认

默认在选题与故事方向、完整剧本、代表性样片三个节点先完成自查、修复与复查，再提供具体成果，请用户判断是否合适，随后推进依赖该决定的工作。选题讨论说明本期讲什么、为何值得讲、事实与类比边界；剧情讨论展示人物愿望、冲突、因果、转折、结尾及代表性对白。用户沟通用于判断创作方向与取舍，Agent 应自行发现和修复的错误先自行处理；自查通过仍不能代替用户对内容和表现的确认，详细节点与记录见 [用户沟通与确认](references/handoff-and-resume.md#用户沟通与确认)。

发现会影响主题、人物动机、剧情逻辑或结尾的疑问时，说明具体问题、影响、可选处理及建议，及时交给用户判断；可自行查证的事实先核验。普通细节和技术修复自主完成，已确认的决定沿用。用户明确授权本次全权创作或跳过某个节点时按其授权推进；未回复不等于确认。

## 阶段自查

每个阶段在提交用户审阅、采用成果或进入下游前，必须执行“读取实际成果 → 按本阶段要求检查 → 定位并修复问题 → 复查受影响成果与衔接 → 保存检查依据”。检查覆盖本次范围内的完整文本、全部采用素材及相应动作/章节，不能仅检查提示词、生成日志或少量样本。分阶段检查范围与放行条件见 [阶段自查与放行](references/handoff-and-resume.md#阶段自查与放行)，实际工具与证据边界见 [检查依据](references/production-execution.md#检查依据与适用边界)。

已发现且可自行修复的问题须先解决，不能交给用户代做质检；修复后检查依赖与衔接，未受影响且检查仍有效的成果可复用。检查记录关联具体文件与版本，区分已通过、需修复和待核验；缺少必要检查条件时保存准确缺口，不把“已生成”“可打开”或“编码成功”称为自查通过。

## 全流程约束

- 剧本以生活故事解释复杂问题，保留人物动机、合理反转、事实边界与可迁移的判断方法；制作已有剧本时保持核心剧情、对白含义和结局。技术分章和表演说明与创作改写分别处理。
- 对白保留符合人物和情境的铺垫、补充、重复、犹豫与长短句变化，不把所有台词压成信息短句或金句。按 [生活化对白](references/scriptwriting.md#对白保留自然说话的过程) 检查人物实际会怎样开口、解释和回应，录音稿沿用确认后的说法。
- 故事画面、角色、道具、特效与封面统一采用选中的二维有限动画形式。场景结构、动作因果、对象状态与信息显示保持连续；创作选择随剧情变化，记录只覆盖实际相关内容。
- 人物视线、道具阅读面与机位保持真实空间关系：人物面对镜头看手机、书、纸条或票据时，可读面朝向人物，镜头看到背面、封皮或背壳。不能为了让观众看清内容，把人物正在阅读的屏幕或文字面翻向镜头；内容展示按 [视线与道具朝向](references/visuals-and-performance.md#视线阅读面与道具朝向) 另安排合乎空间关系的镜头。
- 逐张检查采用姿势的肢体数量、连接、关节与支撑，并检查连续换帧中的头身转向、手脚归属和重影；多手、多脚、肢体粘连、异常扭转或需要转身却只换头朝向的结果须修复。按 [肢体与头身动作检查](references/visuals-and-performance.md#肢体与头身动作检查) 区分自然的小幅转头和需要肩、躯干及下肢配合的大幅转向，修复后复查完整动作段。
- 每个动作、表情及嘴形变化交付可直接替换的完整姿势图片，同一姿势组固定画布尺寸、角色比例和定位基准。角色姿势包含完整角色及随动作一起表现的道具，不生成独立嘴部、头部或肢体片段再拼接；需要整体表现互动时使用完整镜头动作图片。具体生成与对齐校验见 [视觉与表演](references/visuals-and-performance.md#完整动作帧与对齐校验)。
- 图片生成及创意编辑统一使用 Image Gen；对白、旁白、选声试听及问题段重生成仅使用 Fish Audio MCP。图片技术整理、排版、动画合成、音频后期、字幕和视频导出使用适合的其他工具；音乐、音效与环境声选取适用的现有素材。实际调用方式以当前 Agent 可用接口的工具说明为准。
- Fish 音色仅从 [配音与音频的限定候选表](references/voice-and-audio.md#mcp-工具就绪与音色选择) 中按角色性别与年龄段选择，旁白也须确定声音设定并从表中选用。试听、正式生成与重生成均明确传入所选 `voice_id`。
- 朗读正文、表演说明、含可选标签的生成文本与定稿配音分别管理。字幕取自标准朗读正文，控制标签、导演说明和读音替代拼写不进入字幕。配音选用以 `audio_manifest.json` 为准，工程处理后的实际声音与剧情动作建立共同成片时间轴。
- 仅交付一个正式完整成片：16:9、1920×1080、24 fps、MP4、H.264/AAC；配套 SRT、三种比例封面及可复用工程，详细规格与清单见阶段参考。样片属于过程成果。
- 根据实际执行记录标注生成、视觉检查、技术检查和听音检查。文件存在、自动转写、抽帧或成功编码分别对应不同检查，不能互相替代。工具或素材暂不可用时保存进度、说明恢复条件，继续可执行的独立工作；恢复后核对已有结果再重试。

## 交付与恢复

按本次目标交付实际文件链接，并更新作品目录中的 `project_state.json`。只写剧本交付剧本及适用说明；动画交付清单在 [动画与交付](references/animation-and-delivery.md)；阶段状态和继续制作所需信息按 [阶段衔接与续作](references/handoff-and-resume.md) 保存。跨聊天恢复先读取记录并核对文件，不能只依据对话中的“已完成”继续。
