# 二维动画创作与制作

将主题转化为有事实依据、生活质感和启发性的原创情景剧，并按用户要求选择简笔水彩画或讽刺手绘卡通形式，制作二维有限动画。支持完整创作，也支持从已有剧本或工程接续制作。

本 Skill 面向所有读取并执行这些规范的 Agent，不限定模型、客户端或执行平台。文中的“Agent”均指当前执行者；按本次任务范围检查工具、权限和运行依赖，只写剧本时无需具备媒体生成与编码能力。

执行本 Skill 的 Agent 负责理解、写作、制作规划、工具调用、代码执行和实际成果检查；图片创作优先即梦，额度或必要能力不可用时使用 Image Gen，相关图片统一整理到即梦画布。按当前实测与用户指定分工，Fish Audio MCP 仅用于选声、试听、配音及音频核验，不用于图片或视频工作；本地合成与编码工具负责动画工程和导出。各阶段以当前执行环境可调用的工具、已保存文件及实际检查为依据。

## 选择本次范围

| 用户目标与现有输入 | 执行模式 | 完成边界 |
| --- | --- | --- |
| 根据主题写故事、写剧本；只提供主题且未要求成片 | 只写剧本 | 完整剧本、适用的来源与类比边界、交接记录 |
| 将用户指定的已有剧本制作成动画 | 已有剧本制作动画 | 从剧本交接开始，完成成片、字幕、封面、发布文案及工程 |
| 根据主题创作并做成完整动画或视频 | 从主题到成片 | 剧本创作与动画制作全流程 |
| 继续已有工程、修改某一部分或修复问题 | 按原模式续作或局部修改 | 用户本次指定的成果与受影响部分的复查 |

以用户最新要求确定范围。明确只写剧本、只做封面或只修复某个镜头时，完成对应部分；要求成片时按确认后的方向持续完成整片。常规细节自行安排；话题是否适合、剧情是否符合用户意图及影响主线的疑问，按下方沟通节点与用户讨论。

## 选择视觉形式与结尾

每个作品选择一种视觉形式，场景、角色、动作图片、特效、封面与导出沿用同一规范：

| 形式 | 适合的表现重点 | 读取规范 |
| --- | --- | --- |
| 简笔水彩画，`simple-watercolor` | 简洁手绘线稿、轻薄淡彩、自然晕染与适量留白，清楚的场景与动作 | [简笔水彩形式](references/style-simple-watercolor.md) |
| 讽刺手绘卡通，`satirical-cartoon` | 简洁线条、强表情、对比构图、荒诞隐喻和反讽余韵 | [卡通形式](references/style-satirical-cartoon.md) |

用户明确指定视觉形式时采用对应形式；续作沿用已记录的选择，明确要求改画风时按变更传播更新素材；全新作品未指定时默认简笔水彩画。将 `visual_style` 和采用规范保存到作品进度记录，只读取选中的形式规范，人物、场景与封面保持同一绘画语言。旧 `japanese-pixel` 标识仅用于识别历史像素工程；改为水彩时使用 `simple-watercolor`，更新美术基准、受影响图片和采样配置，并复查关键帧及样片，不能只改标识就将旧像素素材作为水彩采用。

结尾独立于画风选择，可以完整收束、留下后续选择，或形成循环反讽的余韵。开放结局仍交代关键因果与已经发生的结果，留下有依据的判断或未来走向；不能以突然截断剧情代替完整作品。按 [剧本的结尾设计](references/scriptwriting.md#结尾设计与观众参与) 构思，在进度记录中保存结尾意图。

只读取当前阶段需要的参考文件。跨阶段时读取下一阶段的要求，续作或修改时补读对应的恢复与变更规则。

## 推进流程

只写剧本：主题与重点问题、必要事实核验及方向讨论 → 完整主剧本自查与用户确认 → 依据确认版本编写上/下或上/中/下分段剧本 → 分段自查、用户审阅与修订 → 保存采用版本及交接记录。主剧本交代完整故事、人物、对白与结局；分段剧本落实各段约 3–5 分钟的内容、看点、悬念与承接，两项分别确认。只写剧本时在文字成果边界停止。

已有剧本制作动画：确认完整主剧本 → 确认分段剧本 → 确认人物、场景和关键道具清单 → 建立标准参考并生成关键变化的首尾帧 → 统一放入即梦画布 → 按剧本补齐缺失关键画面并确认画布 → 根据首尾帧规划中间姿势 → 以上一合格帧逐帧生成、自查和补帧 → 确认实际样片 → 扩展其余完整动作并按剧本分段合成、导出及交付。已有明确覆盖相应内容的确认可沿用，不能凭一个“剧本已确认”跳过尚未审阅的分段与清单。

从主题到成片：先完成完整主剧本与分段剧本的两次内容确认，再按上述清单、首尾帧、画布与中间帧顺序衔接动画制作。阶段交付用于展示可审阅成果、收集反馈和保存进度；满足相应确认与交接条件后，在用户已授权的范围内继续推进，待核验项按能力边界记录。

分段剧本确认后可整理录音稿和待审阅清单；清单确认后，按 [即梦画布与生图路由](references/canvas-and-image-routing.md) 才开始标准参考与关键首尾帧生成，可与已具备输入的配音工作并行。关键画面补齐并经用户确认后，先完成样片所需的中间帧与实际切换检查，样片确认后再扩展其余动作。真实配音核验后确定最终表演、嘴形和字幕定时。并行工作须满足各自上游确认，不能提前批量生成中间帧。封面创意可提前构思，实际生图遵守清单与视觉基准，最终配套对照成片复核。

## 用户沟通与确认

依次确认完整主剧本、分段剧本、人物/场景/关键道具清单、已补齐关键画面的首尾帧画布，再确认代表性动画样片。每个节点先完成自查、修复与复查，提供实际文件、清单或画布供用户判断；当前节点未确认时暂停依赖它的下一阶段，不能以自查通过代替用户确认。选题或故事方向尚有分歧时先讨论，已有决定沿用。详细成果、确认范围与版本记录见 [用户沟通与确认](references/handoff-and-resume.md#用户沟通与确认)。

发现会影响主题、人物动机、剧情逻辑或结尾的疑问时，说明具体问题、影响、可选处理及建议，及时交给用户判断；可自行查证的事实先核验。普通细节和技术修复自主完成，已确认的决定沿用。用户明确授权本次全权创作或跳过某个节点时按其授权推进；未回复不等于确认。

## 阶段自查

每个阶段在提交用户审阅、采用成果或进入下游前，必须执行“读取实际成果 → 按本阶段要求检查 → 定位并修复问题 → 复查受影响成果与衔接 → 保存检查依据”。检查覆盖本次范围内的完整文本、全部采用素材及相应动作/叙事段，不能仅检查提示词、生成日志或少量样本。分阶段检查范围与放行条件见 [阶段自查与放行](references/handoff-and-resume.md#阶段自查与放行)，实际工具与证据边界见 [检查依据](references/production-execution.md#检查依据与适用边界)。

已发现且可自行修复的问题须先解决，不能交给用户代做质检；修复后检查依赖与衔接，未受影响且检查仍有效的成果可复用。检查记录关联具体文件与版本，区分已通过、需修复和待核验；缺少必要检查条件时保存准确缺口，不把“已生成”“可打开”或“编码成功”称为自查通过。

## 全流程约束

- 从话题生成的最终分段剧本按“上、下”或“上、中、下”组织，每段目标约 3–5 分钟，不以章、节作为故事结构；先确认完整主剧本，再编写并确认分段版本。每段具备独立看点、推进与回报，上段及中段留有伏笔支撑的后续悬念，后段兑现，最后一段完成主线。具体方法见 [分段剧情与悬念](references/scriptwriting.md#按上下或上中下组织剧情)。用户指定的已有剧本沿用明确确认的内容和结构。
- 创作或按用户要求改编时，逐段合理丰富情境、人物动机、冲突、行动、转折与后果，形成能支撑本段时长的戏剧性；把关键情节写成可见动作、场景互动、状态变化和人物反应，为后续生成动画提供明确依据。按 [逐段改编与戏剧化展开](references/scriptwriting.md#逐段改编与戏剧化展开) 完成后再进入录音稿和镜头制作，不能仅将原素材切段或扩写解释性对白。
- 剧本以生活故事解释复杂问题，保留人物动机、合理反转、事实边界与可迁移的判断方法；制作已有剧本时保持核心剧情、对白含义和结局。技术拆段和表演说明与创作改写分别处理。
- 对白保留符合人物和情境的铺垫、补充、重复、犹豫与长短句变化，不把所有台词压成信息短句或金句。按 [生活化对白](references/scriptwriting.md#对白保留自然说话的过程) 检查人物实际会怎样开口、解释和回应，录音稿沿用确认后的说法。
- 动作与场景交互是叙事要求。每场明确人物正在做的事及与道具、空间、他人的关系，用可见行动、接触、状态变化和回应推进剧情；不得把固定背景前两个小人轮流说话作为全片的默认表现。按 [动作与场景交互](references/visuals-and-performance.md#动作与场景交互) 设计人物调度和镜头，样片展示实际互动，整场与整段自查检查交互和观看节奏。
- 关键事件按 [叙事连续性](references/story-continuity.md) 核对目标/决定、启动执行、必要过程或合理省略、结果/交接、人物回应与下一步选择。事件因果、镜头/场景边界和动作帧分别检查；途中可以省略，关键状态改变与信息来源须有实际呈现或可信线索，不能从“决定去做”直接跳成“已经完成”。先补叙事和镜头缺口，再补组内动作帧，不机械将每一环拆成独立镜头或对白。
- 故事画面、角色、道具、特效与封面统一采用选中的二维有限动画形式。场景结构、动作因果、对象状态与信息显示保持连续；创作选择随剧情变化，记录只覆盖实际相关内容。
- 人物视线、道具阅读面与机位保持真实空间关系：人物面对镜头看手机、书、纸条或票据时，可读面朝向人物，镜头看到背面、封皮或背壳。不能为了让观众看清内容，把人物正在阅读的屏幕或文字面翻向镜头；内容展示按 [视线与道具朝向](references/visuals-and-performance.md#视线阅读面与道具朝向) 另安排合乎空间关系的镜头。
- 逐张检查采用姿势的肢体数量、连接、关节与支撑，并检查连续换帧中的头身转向、手脚归属和重影；多手、多脚、肢体粘连、异常扭转或需要转身却只换头朝向的结果须修复。按 [肢体与头身动作检查](references/visuals-and-performance.md#肢体与头身动作检查) 区分自然的小幅转头和需要肩、躯干及下肢配合的大幅转向，修复后复查完整动作段。
- 每个表情、动作、嘴形及道具/环境等可见变化单元的完整序列，至少使用 6 张承载该变化的有效不同图片，包括首尾与必要过渡，样片和正式动画均适用；复杂变化继续增加。首尾关键帧阶段可先只有两张，不能因此标记完整动作已通过。图片仍为完整角色姿势、完整镜头或对应完整对象/效果帧，同组固定画布、比例与定位；角色不拆嘴、头或肢体拼接，重复静帧、复制文件及增加输出帧数不计数。计数与检查见 [变化单元与图片下限](references/visuals-and-performance.md#变化单元与至少六张有效图片)。
- 清单确认后先建立标准人物参考与镜头基准，为关键变化生成首帧和尾帧，入画布并补齐缺失关键画面；首尾与画布确认后再规划中间姿势。实际连续序列以上一张合格帧为编辑目标逐帧微调，标准图锁定身份，尾帧约束动作终点；每帧检查后继续，最后检查与预先生成尾帧的衔接。首尾帧可先独立生成用于规划，不能把两张关键图当作已完成连续动画。流程与 12 帧示例见 [视觉与表演](references/visuals-and-performance.md#标准参考图与上一帧微调)。
- 没有直接生成连续动画的能力时，按每个变化单元至少 6 张有效不同图片的下限生成完整序列，再根据动作跨度、接触、转向与播放检查增加过渡帧，通过 [多帧顺序切换](references/visuals-and-performance.md#用多帧切换补足连续动作) 模拟连续动作。六张是下限，不是上限或连续性通过的依据；不能用重复静帧冒充补帧或因工具限制退回固定站位对白。
- 图片生成及创意编辑优先通过 `dreamina-canvas-cli` 技能使用即梦，先检查额度、报价与执行条件；额度或必要能力不可用时按 `imagegen` 技能使用 Image Gen，结果统一导入同一作品画布，排列好以便观察与补帧，并保存本地文件与来源。具体路由、待确认/未知任务处理及画布恢复见 [即梦画布与生图路由](references/canvas-and-image-routing.md)。对白、旁白、选声试听及问题段重生成仅使用 Fish Audio MCP。图片技术整理、排版、动画合成、音频后期、字幕和视频导出使用适合的其他工具；音乐、音效与环境声选取适用的现有素材。实际调用方式以当前 Agent 可用接口的工具说明为准。
- Fish Audio MCP 的适用范围固定为音频，不列为图片、视频或图生视频的候选与备用工具，也不用于自动口型或数字人视觉生成。停止沿用旧的 Fish 图片/视频测试及报价计划；工具目录、模型列表或音频积分余额不能作为在本流程恢复这些任务的依据。
- Fish 音色仅从 [配音与音频的限定候选表](references/voice-and-audio.md#mcp-工具就绪与音色选择) 中按角色性别与年龄段选择，旁白也须确定声音设定并从表中选用。试听、正式生成与重生成均明确传入所选 `voice_id`。
- 朗读正文、表演说明、含可选标签的生成文本与定稿配音分别管理。字幕取自标准朗读正文，控制标签、导演说明和读音替代拼写不进入字幕。配音选用以 `audio_manifest.json` 为准，工程处理后的实际声音与剧情动作建立共同成片时间轴。
- 动画按采用剧本的“上、下”或“上、中、下”分别制作与导出，交付对应的两段或三段正式 MP4，每段目标约 3–5 分钟；用户只要求某段时限定本次范围。每段均为 16:9、1920×1080、24 fps、H.264/AAC，配套本段 SRT、三种比例封面与发布文案，共用可复用工程并保留段间状态和悬念衔接。每段仅选用一个当前正式版本，样片属于过程成果；详细规格与清单见 [分段成片交付](references/animation-and-delivery.md#阶段与最终交付)。
- 根据实际执行记录标注生成、视觉检查、技术检查和听音检查。文件存在、自动转写、抽帧或成功编码分别对应不同检查，不能互相替代。工具或素材暂不可用时保存进度、说明恢复条件，继续可执行的独立工作；恢复后核对已有结果再重试。
